🌟 Real-Life Analogy (10th-Grade Mental Model)

Think of ordering food at a restaurant. FROM is telling the waiter which kitchen or menu you are choosing from. WHERE is filtering out items you don't like (e.g. No dairy, No nuts). SELECT is picking the exact dishes you want placed on your table. And ORDER BY is deciding what gets served first (Starters first, Dessert last). Notice that even though you write SELECT first on the page, the restaurant must go to the kitchen (FROM) and filter the ingredients (WHERE) long before they can serve your plate (SELECT)! Restaurant me khana order karne ki misaal lein: FROM kitchen chunnna hai. WHERE filter lagana hai (jaise non-veg nahi chahiye). SELECT plate me parosna hai. Aur ORDER BY decide karna hai ki pehle starter aayega ya dessert. Halanki hum SELECT pehle likhte hain, lekin database pehle kitchen (FROM) me jaata hai, filter (WHERE) karta hai, aur baad me plate (SELECT) banata hai!

🗣️ How to Speak in an Interview (Crisp Speaking Points)
  • True Order of Execution of SQL (Critical Interview Question!):
    1. FROM & JOIN (Identify tables)
    2. WHERE (Filter individual rows)
    3. GROUP BY (Aggregate rows)
    4. HAVING (Filter groups)
    5. SELECT (Compute expressions & column projections)
    6. DISTINCT (Remove duplicate projection rows)
    7. ORDER BY (Sort the result set)
    8. LIMIT / OFFSET (Slice output window)
  • Why can't you use column aliases in the WHERE clause? Because WHERE is executed at Step 2, while SELECT (which creates the alias) is not executed until Step 5!
  • Why does salary = NULL return zero rows? In SQL, NULL represents an 'unknown' value, not zero or empty string. Any comparison with NULL using = or != evaluates to UNKNOWN. You must always use IS NULL or IS NOT NULL.
  • LIKE Wildcards: % matches zero or more characters; _ matches exactly one character.
  • Pagination Pitfall with OFFSET: OFFSET 1000000 LIMIT 20 forces the database to read and discard 1,000,000 rows. In high-performance systems, prefer Keyset Pagination (Cursor Pagination: WHERE id > last_seen_id LIMIT 20).

1. Anatomy of the SELECT Query

The SELECT statement is the heart of SQL. It retrieves specified columns from one or more tables. Instead of writing SELECT * (which pulls every single column and wastes network bandwidth), production applications specify the exact columns required.

We can rename columns in the output using the AS keyword (aliasing), and eliminate duplicate rows from the final result set using DISTINCT.

2. Filtering Data: Comparison, Logical, and Set Operators

The WHERE clause extracts only those records that fulfill a specified condition. We combine conditions using boolean logic:

• AND: All conditions must be true.
• OR: At least one condition must be true.
• NOT: Inverts a condition.
• IN (val1, val2...): Replaces messy chains of multiple OR statements.
• BETWEEN low AND high: Inclusive range check (equivalent to col >= low AND col <= high).

3. The Three-Valued Logic of SQL & NULL Handling

Unlike programming languages where boolean expressions are either TRUE or FALSE, SQL operates on Three-Valued Logic: TRUE, FALSE, and UNKNOWN.

Because NULL signifies missing or unknown information, comparing two unknowns (NULL = NULL) is logically UNKNOWN (treated as false in a WHERE clause). To safely handle NULLs, SQL provides IS NULL, IS NOT NULL, and the COALESCE(col, fallback) function.

Practical Hands-On Code Demonstrations

Code Example 1: Basic SELECT with Expressions and Aliases

sql
SELECT 
    emp_id AS employee_identifier,
    CONCAT(first_name, ' ', last_name) AS full_name,
    salary,
    salary * 12 AS annual_package,
    ROUND(salary * 0.18, 2) AS estimated_tax
FROM employees
WHERE is_active = TRUE;
• Computations like salary * 12 happen on the fly in memory during query execution.

Code Example 2: Complex Filtering with AND, OR, and Parentheses

sql
-- Find high earners in Engineering OR managers in any department
SELECT emp_name, department, job_title, salary
FROM employees
WHERE (department = 'Engineering' AND salary >= 90000)
   OR (job_title LIKE '%Manager%');
• Always use parentheses around AND and OR blocks to avoid unexpected operator precedence bugs!

Code Example 3: Pattern Matching with LIKE and Wildcards

sql
-- 1. Names starting with 'A'
SELECT * FROM customers WHERE customer_name LIKE 'A%';

-- 2. Email addresses from gmail.com
SELECT * FROM customers WHERE email LIKE '%@gmail.com';

-- 3. Four-letter names where second letter is 'o' (e.g. John, Tony)
SELECT * FROM customers WHERE customer_name LIKE '_o__';
• % matches any length of characters; _ matches exactly one character.

Code Example 4: The IN, NOT IN, and BETWEEN Operators

sql
-- Orders placed in Q1 between Jan 1 and March 31
SELECT order_id, order_date, amount, status
FROM orders
WHERE order_date BETWEEN '2024-01-01' AND '2024-03-31'
  AND status IN ('DELIVERED', 'SHIPPED')
  AND payment_method NOT IN ('CASH_ON_DELIVERY');
• IN ('DELIVERED', 'SHIPPED') is much cleaner and faster than writing status = 'DELIVERED' OR status = 'SHIPPED'.

Code Example 5: Handling NULLs with IS NULL and COALESCE

sql
-- Replace NULL phone numbers with a friendly placeholder
SELECT 
    customer_id,
    customer_name,
    COALESCE(phone_number, 'No Phone Provided') AS contact_phone,
    COALESCE(referrer_id, 0) AS referral_code
FROM customers
WHERE phone_number IS NULL;
• COALESCE returns the first non-null argument in its list.

Code Example 6: Sorting and Pagination with ORDER BY, LIMIT, and OFFSET

sql
-- Fetch Page 2 of top-earning employees (10 records per page)
SELECT emp_id, emp_name, department, salary
FROM employees
ORDER BY salary DESC, emp_name ASC
LIMIT 10 OFFSET 10;
• LIMIT 10 OFFSET 10 skips the first 10 rows and returns the next 10 (rows 11-20).

⚠️ Common Beginner & Production Mistakes
  • Writing WHERE column = NULL: This will never return any rows! Always write WHERE column IS NULL.
  • Referencing a SELECT alias in the WHERE clause: Writing SELECT salary * 12 AS annual FROM emp WHERE annual > 50000; causes a syntax error because WHERE runs before SELECT assigns the alias.
  • Forgetting parentheses with mixed AND/OR: AND has higher precedence than OR, which can lead to severe security leaks (e.g. leaking admin accounts).
💡 Senior Database Engineer Pro Tips
  • Leading Wildcard Performance Warning: LIKE '%abc' cannot use standard B-Tree indexes and forces a full table scan. If you need suffix searching, use reverse indexing or trigram indexes (pg_trgm).
  • Keyset (Cursor) Pagination over OFFSET: Instead of OFFSET 10000, store the last seen id and write WHERE id > 10000 ORDER BY id ASC LIMIT 20. This executes in constant time O(1) instead of linear scan O(N)!
⚑ Quick Recap & Key Takeaways
  • SQL execution order: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT.
  • Always use IS NULL and IS NOT NULL to check for missing values.
  • COALESCE provides graceful default values when encountering NULL.
  • LIKE uses % for multi-character wildcards and _ for single-character wildcards.
  • Use parentheses to group logical expressions explicitly when combining AND and OR.

Exercise 2: Retrieve the product_name, price, and a calculated column discounted_price (10% off) for all products with price between 50 and 200, excluding products where is_discontinued = TRUE.

💡 Hint: Use BETWEEN 50.00 AND 200.00 and is_discontinued = FALSE.

Show Solution

    product_name,
    price,
    ROUND(price * 0.90, 2) AS discounted_price
FROM products

  AND is_discontinued = FALSE;
Hard

Exercise 3: Explain why SELECT emp_name, salary * 12 AS annual_sal FROM employees WHERE annual_sal > 60000; fails with an 'unknown column' error in SQL, and how to fix it.

💡 Hint: Think about the order of query execution.

Show Solution 
-- Reason: The SQL engine processes the WHERE clause BEFORE the SELECT clause.
-- At the moment WHERE executes, the alias 'annual_sal' does not exist yet!
-- Fix Option 1 (Repeat expression in WHERE):
SELECT emp_name, salary * 12 AS annual_sal
FROM employees
WHERE (salary * 12) > 60000;

-- Fix Option 2 (Use CTE / Subquery):
WITH emp_annual AS (
    SELECT emp_name, salary * 12 AS annual_sal FROM employees
)
SELECT * FROM emp_annual WHERE annual_sal > 60000;
