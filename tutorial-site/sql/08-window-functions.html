🌟 Real-Life Analogy (10th-Grade Mental Model)

Think of a marathon race with 10,000 runners. If you run GROUP BY age_group, the database collapses all runners into a single average time per age group — the individual runners disappear! A Window Function is like assigning a digital race certificate to EVERY individual runner. Each runner stays on the screen with their name and time, but their certificate also shows: 'You ranked 4th in your age group (RANK)', 'You were 12 seconds behind the runner in front of you (LAG)', and 'The cumulative time of your team so far is 4 hours (Running Total)'. No runners are collapsed! Marathon daud ki misaal lein: GROUP BY karne se saare daudne wale gayab ho jaate hain aur bas har category ka ek average number bachta hai. Window Function har runner ki row ko bachaye rakhta hai: har runner ka naam dikhega, aur sath me ek extra column me dikhega ki 'Aap apni category me 2nd rank par ho (DENSE_RANK)' aur 'Aapse aage wala runner kitna aage tha (LAG)'. Data collapse nahi hota!

🗣️ How to Speak in an Interview (Crisp Speaking Points)
  • Window Function vs GROUP BY: GROUP BY collapses multiple rows into a single summary row per group. A Window Function performs calculations across a set of related rows but preserves the individual identity of every original row.
  • ROW_NUMBER vs RANK vs DENSE_RANK (Top #1 Interview Question!):
    Suppose three students tie with score 95: (100, 95, 95, 80).
    • ROW_NUMBER(): Assigns strictly sequential unique integers: 1, 2, 3, 4.
    • RANK(): Assigns identical ranks to ties, then SKIPS the next rank: 1, 2, 2, 4 (rank 3 is skipped!).
    • DENSE_RANK(): Assigns identical ranks to ties, but DOES NOT SKIP: 1, 2, 2, 3.
  • LAG and LEAD: LAG(col, 1) accesses the value from the previous row; LEAD(col, 1) accesses the value from the following row. Eliminates slow, painful self-joins.
  • Default Window Frame: When ORDER BY is present inside OVER(), the default frame is RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW. For true physical running totals, specify ROWS BETWEEN ....
  • Can you use Window Functions in a WHERE clause? NO! Window functions execute after the WHERE, GROUP BY, and HAVING clauses. To filter on a window calculation, wrap it in a CTE or derived table subquery!

1. What is a Window Function?

In standard SQL, you face a dilemma: if you use aggregate functions like SUM() or AVG() with GROUP BY, you lose the individual row details.

Window Functions solve this by computing an aggregate or analytic value over a 'window' (subset) of rows while retaining every individual row in the final result set.

2. The OVER Clause and PARTITION BY

The OVER clause defines the window of rows that the function operates on. It accepts two primary clauses:

• PARTITION BY column: Divides the rows into groups (windows). The calculation resets at the start of each partition.
• ORDER BY column: Specifies the sequence in which rows are processed inside each partition.

3. Value Functions: LAG() and LEAD()

In time-series analysis and financial reporting, you frequently need to compare the current month's sales with the previous month's sales to calculate growth rates.

Before window functions, developers had to write messy, slow SELF JOINs on dates. With LAG() and LEAD(), you look backward or forward in the result set in a single line of code.

Practical Hands-On Code Demonstrations

Code Example 1: Demonstrating ROW_NUMBER(), RANK(), and DENSE_RANK() on Ties

sql
SELECT 
    student_name,
    score,
    ROW_NUMBER() OVER (ORDER BY score DESC) AS row_num,
    RANK()       OVER (ORDER BY score DESC) AS rnk,
    DENSE_RANK() OVER (ORDER BY score DESC) AS dense_rnk
FROM exam_scores;
• Notice how ties are handled: ROW_NUMBER gives 1,2,3; RANK gives 1,2,2,4; DENSE_RANK gives 1,2,2,3.

Code Example 2: Partitioning by Category: Top Earners per Department

sql
WITH ranked_employees AS (
    SELECT 
        emp_id,
        emp_name,
        department,
        salary,
        DENSE_RANK() OVER (
            PARTITION BY department 
            ORDER BY salary DESC
        ) AS dept_salary_rank
    FROM employees
)
SELECT * 
FROM ranked_employees
WHERE dept_salary_rank <= 2; -- Top 2 highest-paid employees in EVERY department!
• PARTITION BY department resets the rank back to 1 for each department. The CTE allows filtering on dept_salary_rank in the outer WHERE clause.

Code Example 3: Month-Over-Month Revenue Growth with LAG()

sql
SELECT 
    sales_month,
    revenue,
    LAG(revenue, 1) OVER (ORDER BY sales_month) AS prev_month_revenue,
    ROUND(
        ((revenue - LAG(revenue, 1) OVER (ORDER BY sales_month)) / 
          LAG(revenue, 1) OVER (ORDER BY sales_month)) * 100, 
        2
    ) AS mom_growth_percent
FROM monthly_financials;
• LAG(revenue, 1) fetches the previous row's revenue, allowing instant percentage growth calculations without a self-join.

Code Example 4: Cumulative Running Total with Window Frames

sql
SELECT 
    order_id,
    order_date,
    order_amount,
    -- Running total calculated from the start of time up to the current row
    SUM(order_amount) OVER (
        ORDER BY order_date
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS cumulative_running_total
FROM orders;
• As the query scans down the table, each row displays the rolling accumulated sum of all prior orders.

Code Example 5: 7-Day Moving Average for Analytics Dashboards

sql
SELECT 
    metric_date,
    active_users,
    ROUND(AVG(active_users) OVER (
        ORDER BY metric_date
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ), 2) AS moving_avg_7_day
FROM daily_metrics;
• ROWS BETWEEN 6 PRECEDING AND CURRENT ROW smooths out weekend dips by averaging the last 7 daily data points.

Code Example 6: Comparing Individual Row to Department Average in the Same Query

sql
SELECT 
    emp_name,
    department,
    salary,
    ROUND(AVG(salary) OVER (PARTITION BY department), 2) AS dept_avg_salary,
    salary - ROUND(AVG(salary) OVER (PARTITION BY department), 2) AS diff_from_dept_avg
FROM employees;
• Every employee row displays their personal salary right next to their department average.

⚠️ Common Beginner & Production Mistakes
  • Trying to use Window Functions in a WHERE clause: Writing WHERE ROW_NUMBER() OVER (...) <= 3 is illegal because WHERE runs before window functions. Always wrap in a CTE!
  • Confusing RANK() and DENSE_RANK(): Using RANK() when you need sequential ranking leads to skipped ranks when ties occur (e.g. 1st, 2nd, 2nd, 4th). Use DENSE_RANK() to avoid gaps.
  • Omitting ORDER BY in running totals: If you write SUM(amount) OVER (PARTITION BY customer) without ORDER BY, the engine computes the grand total for the customer on every row, rather than a running incremental total!
💡 Senior Database Engineer Pro Tips
  • WINDOW clause reusability: If multiple window functions use the same window specification, name it using the WINDOW clause: WINDOW w AS (PARTITION BY dept ORDER BY salary DESC) and reuse it as OVER w.
  • The Nth Highest Salary Pattern: The cleanest way to solve LeetCode 177/178 (Nth highest salary) is WITH r AS (SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rank FROM emp) SELECT DISTINCT salary FROM r WHERE rank = N;.
⚑ Quick Recap & Key Takeaways
  • Window functions perform analytical calculations without collapsing individual rows.
  • ROW_NUMBER produces consecutive unique numbers (1,2,3,4).
  • RANK assigns ties equal values and skips subsequent numbers (1,2,2,4).
  • DENSE_RANK assigns ties equal values without skipping (1,2,2,3).
  • LAG() looks backward; LEAD() looks forward in the result set.

Medium

Exercise 2: Write a query using a CTE and DENSE_RANK() to find the 2nd highest salary in the entire employees table.

💡 Hint: Use WITH ranked AS (SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk FROM employees) SELECT DISTINCT salary FROM ranked WHERE rnk = 2.

Show Solution 
WITH ranked_salaries AS (
    SELECT 
        salary,
        DENSE_RANK() OVER (ORDER BY salary DESC) AS salary_rank
    FROM employees
)
SELECT DISTINCT salary AS second_highest_salary
FROM ranked_salaries
WHERE salary_rank = 2;
Hard

Exercise 3: Given a table daily_sales (sale_date, amount), write a query that outputs sale_date, amount, prev_day_amount, and daily_change (current day amount minus previous day amount).

💡 Hint: Use LAG(amount, 1) OVER (ORDER BY sale_date).

Show Solution 
SELECT 
    sale_date,
    amount,
    LAG(amount, 1) OVER (ORDER BY sale_date) AS prev_day_amount,
    amount - LAG(amount, 1) OVER (ORDER BY sale_date) AS daily_change
FROM daily_sales
ORDER BY sale_date ASC;
