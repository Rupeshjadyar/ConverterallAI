🗣️ How to Speak in an Interview (Crisp Speaking Points)
  • Pattern 1: Nth Highest Salary: Always clarify if ties exist! If ties exist, use DENSE_RANK(). Never use simple LIMIT 1 OFFSET N-1 without deduplication.
  • Pattern 2: Delete Duplicate Rows: Use a CTE with ROW_NUMBER() OVER (PARTITION BY unique_fields ORDER BY id) and delete where row_num > 1.
  • Pattern 3: Consecutive Streaks (Gaps & Islands): Compute the difference between the chronological date and a sequential ROW_NUMBER(). The difference remains constant during consecutive day streaks!
  • Pattern 4: Cumulative Running Totals: Use SUM(amount) OVER (PARTITION BY ... ORDER BY ... ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW).
  • Pattern 5: Department Top N Performers: Use a CTE with DENSE_RANK() OVER (PARTITION BY dept ORDER BY salary DESC) and filter where rank <= N in the outer query.

2. Top Conceptual Interview Q&A (Rapid Fire)

In phone screens and technical rounds, hiring managers test foundational clarity with rapid-fire questions:

• Q: Difference between TRUNCATE and DELETE? A: TRUNCATE is DDL (fast page deallocation, resets sequences, minimal logging, no WHERE). DELETE is DML (row-by-row, logs all deletions, triggers fire, accepts WHERE).
• Q: Difference between WHERE and HAVING? A: WHERE filters rows before grouping; HAVING filters aggregated groups after GROUP BY.
• Q: What is a Clustered Index? A: Dictates physical storage order on disk (one per table, usually PK). Leaf nodes contain actual data.
• Q: What happens if NOT IN encounters a NULL? A: Condition evaluates to UNKNOWN and returns ZERO rows. Always use NOT EXISTS instead.

3. Senior Architecture & Schema Design Questions

For Senior and Full-Stack roles, interviews transition to database architecture:

• How do you handle multi-tenant databases? (Shared database with tenant_id vs separate schemas vs separate databases per tenant).
• How do you scale writes? (Read replicas for reads, table sharding/partitioning, asynchronous message queues for buffer writes).
• When would you pick PostgreSQL over MongoDB? (When you need ACID transactions, complex relational joins, data integrity constraints, and financial auditability).

Practical Hands-On Code Demonstrations

Code Example 1: Interview Challenge 1: Find the 2nd (or Nth) Highest Salary

sql
-- Method A: Universal Best Practice (Handles ties cleanly!)
WITH ranked_salaries AS (
    SELECT 
        salary,
        DENSE_RANK() OVER (ORDER BY salary DESC) AS rank_pos
    FROM employees
)
SELECT DISTINCT salary AS second_highest_salary
FROM ranked_salaries
WHERE rank_pos = 2;

-- Method B: Subquery Approach (Works in older legacy SQL)
SELECT MAX(salary) AS second_highest_salary
FROM employees
WHERE salary < (
    SELECT MAX(salary) FROM employees
);
• Method A with DENSE_RANK is preferred by interviewers because changing rank_pos = 2 to N solves any Nth rank trivially.

Code Example 2: Interview Challenge 2: Delete Duplicate Rows Keeping Only the Lowest ID

sql
-- Table: contacts (id, email, full_name)
-- We want to keep row with min(id) and delete duplicates

-- In PostgreSQL:
DELETE FROM contacts
WHERE id IN (
    SELECT id FROM (
        SELECT id, ROW_NUMBER() OVER (PARTITION BY email ORDER BY id ASC) AS rn
        FROM contacts
    ) t
    WHERE t.rn > 1
);

-- In MySQL using Self Join:
DELETE c1 FROM contacts c1
JOIN contacts c2 ON c1.email = c2.email AND c1.id > c2.id;
• ROW_NUMBER() OVER (PARTITION BY email ORDER BY id ASC) assigns 1 to the first record and 2, 3... to duplicates. Deleting where rn > 1 cleans duplicates safely.

Code Example 3: Interview Challenge 3: Consecutive Active Login Days (Gaps and Islands)

sql
-- Find users with 3 or more consecutive active login days
WITH login_groups AS (
    SELECT 
        user_id,
        login_date,
        -- Magic: Date minus row_number produces a constant anchor date for consecutive days!
        DATE_SUB(login_date, INTERVAL ROW_NUMBER() OVER (
            PARTITION BY user_id ORDER BY login_date
        ) DAY) AS streak_group
    FROM user_logins
)
SELECT 
    user_id,
    MIN(login_date) AS streak_start,
    MAX(login_date) AS streak_end,
    COUNT(*) AS consecutive_days
FROM login_groups
GROUP BY user_id, streak_group
HAVING COUNT(*) >= 3;
• The famous Gaps and Islands trick: subtracting row_number from date produces an identical grouping anchor date for all consecutive days!

Code Example 4: Interview Challenge 4: Top 3 Highest Earners in EACH Department

sql
WITH dept_rankings AS (
    SELECT 
        emp_id,
        emp_name,
        department,
        salary,
        DENSE_RANK() OVER (
            PARTITION BY department 
            ORDER BY salary DESC
        ) AS sal_rank
    FROM employees
)
SELECT department, emp_name, salary, sal_rank
FROM dept_rankings
WHERE sal_rank <= 3
ORDER BY department, sal_rank;
• A standard FAANG interview question testing window partitions and CTE filtering.

Code Example 5: Interview Challenge 5: Find Employees Who Earn More Than Their Direct Manager

sql
SELECT 
    e.emp_name AS employee,
    e.salary AS emp_salary,
    m.emp_name AS manager,
    m.salary AS mgr_salary
FROM employees e
JOIN employees m ON e.manager_id = m.emp_id
WHERE e.salary > m.salary;
• Tests self-join proficiency and understanding table aliasing.

Code Example 6: Interview Challenge 6: Rolling 7-Day Cumulative Revenue

sql
SELECT 
    order_date,
    daily_revenue,
    SUM(daily_revenue) OVER (
        ORDER BY order_date
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) AS rolling_7_day_revenue
FROM daily_revenue_summary;
• Analytical window frame specification for finance and business intelligence dashboards.

⚠️ Common Beginner & Production Mistakes
  • Using LIMIT 1 OFFSET 1 for 2nd highest salary: If two employees tie for 1st place with 90k, LIMIT 1 OFFSET 1 returns 90k (the other 1st place employee!), failing the interview question. Always use DENSE_RANK()!
  • Forgetting to specify ON DELETE CASCADE: In schema design interviews, omitting cascading rules shows a lack of production experience.
  • Using string types for dates or numbers: Storing dates as VARCHAR(20) makes range queries and sorting impossible to index.
💡 Senior Database Engineer Pro Tips
  • Always ask clarifying questions before writing SQL in an interview: 'Can there be NULL values?', 'Can salaries tie?', 'How large is this table in production?', 'Is write performance or read performance our priority?'. Interviewers look for these questions!
  • Think about indexes out loud: When writing a query with JOIN and WHERE, say: 'In production, I would ensure we have an index on (customer_id, status) to make this query execute in milliseconds.'
⚑ Quick Recap & Key Takeaways
  • Always use DENSE_RANK() to solve Nth highest salary problems to handle ties gracefully.
  • Delete duplicate records using a ROW_NUMBER() CTE with PARTITION BY.
  • Solve consecutive day streaks using the date minus row_number grouping anchor.
  • Self joins resolve parent-child employee-to-manager reporting structures.
  • Ask clarifying questions on NULLs, ties, and data volume during interviews.

Hard

Exercise 3: Given a table trips (id, client_id, driver_id, city_id, status, request_at), write a query to compute the cancellation rate of requests with unbanned users (both client and driver must not be banned) each day between '2024-10-01' and '2024-10-03', rounded to 2 decimal places.

💡 Hint: Use WHERE to filter out banned users, and calculate SUM(status != 'completed') / COUNT(*).

Show Solution 
SELECT 
    t.request_at AS day,
    ROUND(
        SUM(CASE WHEN t.status != 'completed' THEN 1.0 ELSE 0.0 END) / COUNT(*), 
        2
    ) AS cancellation_rate
FROM trips t
JOIN users c ON t.client_id = c.users_id AND c.banned = 'No'
JOIN users d ON t.driver_id = d.users_id AND d.banned = 'No'
WHERE t.request_at BETWEEN '2024-10-01' AND '2024-10-03'
GROUP BY t.request_at
ORDER BY t.request_at ASC;
