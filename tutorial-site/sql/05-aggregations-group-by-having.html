Aggregations, GROUP BY & The Crucial HAVING Clause

Master SQL aggregate functions (COUNT, SUM, AVG, MIN, MAX), group datasets into meaningful business summaries with GROUP BY, and understand the difference between WHERE and HAVING in technical interviews. Aggregate functions (COUNT, SUM, AVG) aur GROUP BY seekhein. Jaanein WHERE aur HAVING me kya farak hota hai jo har interview me pucha jaata hai.

  • The #1 SQL Interview Distinction: WHERE (row filter) vs HAVING (aggregate group filter).

🌟 Real-Life Analogy (10th-Grade Mental Model)

Think of sorting coins in your piggy bank. WHERE is examining each single coin BEFORE grouping — you throw away any foreign currency or fake plastic coins. GROUP BY is organizing the remaining valid coins into piles: a pile of 1-dollar coins, a pile of 5-dollar coins, and a pile of 10-dollar coins. HAVING is filtering the PILES AFTER grouping — for example: 'Only give me piles that have more than 50 dollars in total value'. You cannot inspect the total value of a pile before the pile has been created! Gullak ke sikke ginne ki misaal lein: WHERE sikko ko alag dher lagane se PEHLE filter karta hai (nakli sikke bahar phenk diye). GROUP BY bache hue sikko ka dher banata hai (1 rupee ke alag, 5 ke alag, 10 ke alag). HAVING dher banne ke BAAD dher par filter lagata hai (jaise 'wahi dher dikhao jisme 100 se zyada rupaye hain'). Dher banne se pehle aap dher ka total nahi nikal sakte!

🗣️ How to Speak in an Interview (Crisp Speaking Points)
  • WHERE vs HAVING (Top Interview Question):
    • WHERE filters individual rows before any grouping occurs. Cannot use aggregate functions (e.g. WHERE SUM(sal) > 5000 is illegal).
    • HAVING filters aggregated groups after the GROUP BY clause is evaluated. Can freely use aggregate functions (e.g. HAVING COUNT(*) >= 5).
  • COUNT(*) vs COUNT(column): COUNT(*) counts every row regardless of NULL values. COUNT(column) counts only rows where that specific column is NOT NULL.
  • Rule of GROUP BY in SELECT: Any non-aggregated column in the SELECT clause MUST appear in the GROUP BY clause. Failing to do so causes a syntax error in ANSI SQL.
  • AVG with NULLs: AVG() ignores NULL rows entirely, calculating sum divided by the count of non-null rows, which can skew averages if NULL represents 0.
  • Performance Tip: Always filter as many rows as possible in the WHERE clause before grouping to reduce the number of rows the engine must sort and aggregate in memory.

1. What are Aggregate Functions?

In standard SQL queries, each row produces an individual output row. Aggregate functions collapse multiple rows into a single summary value. The 5 foundational aggregate functions are:

• COUNT(expr): Total number of rows.
• SUM(col): Total mathematical sum of a numeric column.
• AVG(col): Arithmetic mean.
• MIN(col): Smallest value (works on numbers, dates, and text!).
• MAX(col): Largest value.

2. Grouping Rows with GROUP BY

When you want aggregations broken down by category — such as total sales per country or average salary per department — you use the GROUP BY clause.

The database partitions the rows by the distinct values of the grouped column, runs the aggregation on each partition, and outputs one summary row per group.

3. The Critical Difference: WHERE vs HAVING

Beginners frequently try to filter aggregates using WHERE: WHERE COUNT(*) > 10. This immediately fails because WHERE executes before rows are grouped!

Remember the execution pipeline: FROM → WHERE → GROUP BY → HAVING → SELECT. Use WHERE to drop rows before grouping, and use HAVING to drop group summaries after grouping.

Practical Hands-On Code Demonstrations

Code Example 1: Demonstrating COUNT(*) vs COUNT(column) with NULLs

sql
-- Table: employees (id, name, bonus)
-- Row 1: (1, 'Alice', 500)
-- Row 2: (2, 'Bob', NULL)
-- Row 3: (3, 'Charlie', 200)

SELECT 
    COUNT(*) AS total_employees,           -- Returns 3
    COUNT(bonus) AS employees_with_bonus,  -- Returns 2 (ignores Bob's NULL!)
    SUM(bonus) AS total_bonus,             -- Returns 700
    AVG(bonus) AS avg_bonus                -- Returns 350 (700 / 2, NOT 700 / 3!)
FROM employees;
• COUNT(bonus) and AVG(bonus) ignore NULLs. If Bob's NULL should count as 0 in the average, write AVG(COALESCE(bonus, 0)).

Code Example 2: GROUP BY with Multiple Aggregations

sql
SELECT 
    department,
    COUNT(*) AS head_count,
    MIN(salary) AS minimum_salary,
    MAX(salary) AS maximum_salary,
    ROUND(AVG(salary), 2) AS average_salary,
    SUM(salary) AS total_payroll
FROM employees
WHERE is_active = TRUE
GROUP BY department
ORDER BY total_payroll DESC;
• One summary row is produced for each unique department.

Code Example 3: Filtering Groups with the HAVING Clause

sql
-- Find departments with at least 5 active employees AND average salary > 75000
SELECT 
    department,
    COUNT(*) AS total_staff,
    ROUND(AVG(salary), 2) AS avg_sal
FROM employees
WHERE is_active = TRUE
GROUP BY department
HAVING COUNT(*) >= 5 
   AND AVG(salary) > 75000.00;
• HAVING filters the resulting groups using aggregate calculations.

Code Example 4: Combining WHERE and HAVING in the Same Query

sql
-- Calculate high-ticket order stats in 2024 for loyal customers
SELECT 
    customer_id,
    COUNT(order_id) AS total_orders,
    SUM(order_amount) AS total_spent
FROM orders
WHERE order_date >= '2024-01-01'  -- WHERE filters individual orders before grouping
  AND status = 'COMPLETED'
GROUP BY customer_id
HAVING SUM(order_amount) > 10000 -- HAVING filters customer groups after summing
ORDER BY total_spent DESC;
• Notice how WHERE eliminates non-2024 or uncompleted orders first, making GROUP BY much faster.

Code Example 5: GROUP BY Across Multiple Columns

sql
-- Sales totals broken down by Year AND Region
SELECT 
    YEAR(order_date) AS order_year,
    shipping_region,
    COUNT(*) AS total_shipments,
    SUM(order_amount) AS gross_revenue
FROM orders
GROUP BY YEAR(order_date), shipping_region
ORDER BY order_year DESC, gross_revenue DESC;
• Multi-column grouping produces combinations: (2024, 'North'), (2024, 'South'), (2023, 'North'), etc.

Code Example 6: Counting Unique Items with COUNT(DISTINCT col)

sql
-- Number of unique customers who bought from each store branch
SELECT 
    store_id,
    COUNT(*) AS total_transactions,
    COUNT(DISTINCT customer_id) AS unique_shoppers
FROM sales
GROUP BY store_id;
• COUNT(DISTINCT customer_id) eliminates repeat purchases by the same customer within the store group.

⚠️ Common Beginner & Production Mistakes
  • Selecting columns not in GROUP BY: Writing SELECT dept, emp_name, AVG(sal) FROM emp GROUP BY dept; is invalid because the engine doesn't know which emp_name to pick for the department group.
  • Using WHERE instead of HAVING for aggregates: Writing WHERE AVG(salary) > 50000 will throw an immediate syntax error.
  • Ignoring NULL impacts on AVG(): Forgetting that AVG() skips NULLs can lead to mathematically incorrect corporate reports.
💡 Senior Database Engineer Pro Tips
  • Filter in WHERE early: Every row you filter in WHERE avoids an expensive in-memory sort or hash aggregation. Never push conditions into HAVING that could have been in WHERE!
  • GROUPING SETS, ROLLUP & CUBE: Advanced SQL provides GROUP BY ROLLUP(year, region) to generate sub-totals and grand totals automatically in a single query.
⚑ Quick Recap & Key Takeaways
  • Aggregate functions (COUNT, SUM, AVG, MIN, MAX) summarize multiple rows into a single value.
  • COUNT(*) counts all rows; COUNT(col) counts non-null rows.
  • GROUP BY categorizes data into summary buckets.
  • WHERE filters rows before grouping; HAVING filters groups after aggregation.
  • Non-aggregated columns in SELECT must be included in the GROUP BY clause.

Hard

Exercise 3: Write a query to find all customer_ids who have placed more than 3 orders in the year 2024 and have spent a grand total of more than $5,000, sorted by total spend descending.

💡 Hint: Use WHERE for the 2024 date filter and HAVING for COUNT > 3 AND SUM > 5000.

Show Solution 
SELECT 
    customer_id,
    COUNT(order_id) AS order_count,
    SUM(order_total) AS total_spent
