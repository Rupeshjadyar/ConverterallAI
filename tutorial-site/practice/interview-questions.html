1. Explain how the JavaScript Event Loop works and the difference between Microtasks and Macrotasks.

Senior JavaScript

JavaScript is strictly single-threaded with a single synchronous Call Stack. When asynchronous operations occur (like setTimeout or fetch), they are handed off to browser Web APIs off-thread.

When completed, their callbacks enter one of two queues:

  • Microtask Queue: Holds Promise callbacks (.then(), .catch()), queueMicrotask(), and MutationObserver. Microtasks have supreme priority: the Event Loop empties the entire microtask queue before moving to the next task!
  • Macrotask Queue (Task Queue): Holds setTimeout, setInterval, and DOM event callbacks. Exactly one macrotask runs per loop tick.
JavaScript
console.log('A');
setTimeout(() => console.log('B'), 0); // Macrotask
Promise.resolve().then(() => console.log('C')); // Microtask
console.log('D');
// Output: A -> D -> C -> B
What the interviewer is testing: Do you understand why setTimeout(fn, 0) does not execute immediately, and how excessive unresolved Promise loops can starve UI rendering.

2. What is a Closure in JavaScript and what are its practical use cases?

Mid-Level JavaScript

A Closure is the combination of a function bundled together with references to its surrounding lexical environment. In JavaScript, every inner function retains access to variables declared in its outer scope, even after that outer function has returned and finished executing!

Practical Use Cases:

  • Data Encapsulation / Private State: Emulating private variables before private class fields existed.
  • Function Factories: Generating configured helper functions (like currying or customized tax calculators).
  • Event Handlers and Callbacks: Preserving parameter state inside loops and async timers.
JavaScript
function createCounter(initialValue = 0) {
  let count = initialValue; // Private variable trapped in closure!
  return {
    increment: () => ++count,
    get: () => count
  };
}
const counter = createCounter(10);
console.log(counter.increment()); // 11
console.log(counter.count);       // undefined (cannot be accessed directly!)

3. How does CSS Specificity work and how is it calculated?

Mid-Level CSS

When multiple conflicting CSS rules target the exact same element, browsers calculate a 4-tier numeric specificity score (Inline, ID, Class/Attribute/Pseudo-class, Element) to determine which rule wins:

  • Inline Styles: (1, 0, 0, 0) — e.g. style="color:red;"
  • IDs: (0, 1, 0, 0) — e.g. #nav-header
  • Classes, Attributes & Pseudo-classes: (0, 0, 1, 0) — e.g. .btn, [type="text"], :hover
  • Elements & Pseudo-elements: (0, 0, 0, 1) — e.g. div, p, ::before
  • Universal Selector: (0, 0, 0, 0) — * adds zero specificity.

Rule: A higher specificity category ALWAYS trumps any amount of lower category selectors. E.g. 1 ID (0, 1, 0, 0) beats 100 classes (0, 0, 100, 0)! !important bypasses the normal cascade and should be used only for utility overrides.

4. Why is Semantic HTML important compared to using generic <div> tags?

Junior HTML

Semantic HTML means using tags that describe the meaning of content (e.g. <header>, <nav>, <main>, <article>, <aside>, <footer>) instead of generic <div> containers. Key benefits:

  • Accessibility (A11y): Screen readers parse landmark tags directly. Visually impaired users can press shortcut keys to jump straight to <nav> or <main> without listening to entire pages.
  • SEO: Search engine web crawlers assign higher relevance to headings inside <article> and <main> while de-prioritizing auxiliary content in <aside>.
  • Maintainability: Clean, self-documenting codebases that are far easier for engineering teams to inspect and refactor.

5. Compare Debounce vs Throttle and provide a real-world scenario for each.

Senior Performance

Both techniques rate-limit high-frequency event handlers, but with different timing semantics:

  • Debounce: Groups multiple consecutive events into a single execution after a specified duration of silence. If new events continue firing before the timer expires, the timer resets.
    Best Scenario: Search box autocomplete API calls or auto-saving user drafts as they type.
  • Throttle: Ensures the callback runs at a steady, fixed rate (at most once every X milliseconds), regardless of how continuously the user triggers the event.
    Best Scenario: Infinite scrolling triggers or browser window resize computations.
