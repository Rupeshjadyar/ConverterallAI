Forms and User Input Fields

Turn static documents into two-way interactive applications that collect user data, selections, and file uploads. User se data lene ke liye forms (<form>), labels, text inputs, checkboxes, dropdowns aur submit buttons banana seekhein.

📚 What You Will Learn
  • The fundamental architecture of <form>: action, method (GET vs POST).
  • Why every input MUST be paired with a <label for="..."> for accessibility.
  • Mastering input types: text, password, email, number, checkbox, radio, date, range, and file.
  • Multi-line inputs with <textarea> and dropdown menus with <select>.
  • The critical difference between type="submit", type="reset", and type="button".
  • Organizing complex forms with <fieldset> and <legend>.
Prerequisites: Completion of 07. Tables & Data Grids.
🌟 Real-Life Analogy: The DMV Driver's License Application

Imagine walking into the Department of Motor Vehicles. An official hands you a clipboard holding a paper application form (<form>). Each blank line has a printed label like "Legal Full Name" (<label>) pointing to a physical blank line where you write (<input type="text">). Multiple choice checkboxes let you pick your organ donor status (checkbox), while mutually exclusive bubble buttons force you to choose one license tier (radio). When you hand the completed paper back across the counter, that physical handover is the Submit action! DMV ya passport office ke application form ki tarah sochiye. Kagaz ka form <form> hai, har khane ke aage likha instruction <label> hai, khali dabba jahan likhte hain woh <input> hai, aur counter par form jama karna Submit button hai.

1. The Form Container and the <label> Requirement

A form is an interactive envelope wrapping user controls. When the user clicks "Submit", the browser packages all input values and sends them to the server defined in the action attribute:

Code Example 1: Accessible Form Baseline

html
<form action="/submit-account" method="POST">
  <!-- CRITICAL ACCESSIBILITY: Explicit label-to-input association -->
  <div class="form-group">
    <label for="user-email">Email Address:</label>
    <input type="email" id="user-email" name="email" required placeholder="you@domain.com">
  </div>

  <button type="submit">Create Account</button>
</form>
The 3 Essential Identifiers on Inputs:
• type="email": Determines what kind of data the user enters and which mobile keyboard appears (with the @ symbol!).
• id="user-email": Matches the label's for="user-email". Clicking the label focuses the input cursor automatically!
• name="email": The key sent to the server in the form payload: email=you@domain.com. If an input lacks a name attribute, its value is never sent to the server!

2. GET vs POST: Choosing the Right Method

The method attribute controls how the browser sends data:

  • GET (Default): Appends all form data directly into the URL query string: search.html?q=javascript&page=1. Used for searches, filters, and read-only lookups. Never use GET for passwords, credit cards, or sensitive data!
  • POST: Packages data inside the hidden HTTP request body payload. Used for account creation, payments, login forms, and file uploads.

Code Example 2: Common Input Types Showcase

html
<!-- 1. Password: Masks characters with black dots -->
<label for="pwd">Password:</label>
<input type="password" id="pwd" name="password" minlength="8" required>

<!-- 2. Number: Numeric keyboard with min, max, and step increments -->
<label for="qty">Quantity:</label>
<input type="number" id="qty" name="quantity" min="1" max="100" value="1">

<!-- 3. Date picker: Native calendar modal -->
<label for="bday">Birthdate:</label>
<input type="date" id="bday" name="birthdate">

<!-- 4. Color picker: Native RGB palette -->
<label for="fav-color">Theme Color:</label>
<input type="color" id="fav-color" name="theme_color" value="#2563eb">
Mobile Optimization: Using type="number" displays a numeric keypad on mobile devices; type="tel" brings up the telephone pad; type="email" brings up the email keyboard.

3. Radio Buttons vs Checkboxes

Students often confuse radio buttons with checkboxes. Here is the distinction:

  • Checkboxes (type="checkbox"): Allow the user to select zero, one, or multiple independent choices.
  • Radio Buttons (type="radio"): Force the user to choose exactly one option from a mutually exclusive group. To group radio buttons together, they must all share the exact same name attribute!

Code Example 3: Radio Button Grouping

html
<p>Choose your payment frequency:</p>

<!-- Notice both inputs share name="billing_cycle" -->
<div>
  <input type="radio" id="bill-monthly" name="billing_cycle" value="monthly" checked>
  <label for="bill-monthly">Pay Monthly ($15/mo)</label>
</div>

<div>
  <input type="radio" id="bill-annual" name="billing_cycle" value="annual">
  <label for="bill-annual">Pay Annually ($120/yr — Save 33%)</label>
</div>
The Magic of name: Because both share name="billing_cycle", selecting one automatically unchecks the other. If you gave them different names, they would behave independently like broken checkboxes!

Code Example 4: Dropdown Menus and Textareas

html
<!-- Dropdown select menu with grouped categories -->
<label for="topic-select">Select Inquiry Topic:</label>
<select id="topic-select" name="topic">
  <optgroup label="Technical Support">
    <option value="bug">Report a Code Bug</option>
    <option value="account">Account Access Issue</option>
  </optgroup>
  <optgroup label="Sales & Partnerships">
    <option value="enterprise">Enterprise License</option>
    <option value="sponsor">Sponsorship</option>
  </optgroup>
</select>

<!-- Multi-line expandable text area (notice: has closing tag!) -->
<label for="message-box">Detailed Feedback:</label>
<textarea id="message-box" name="message" rows="5" placeholder="Type here..."></textarea>
Syntax Note: Unlike <input>, <textarea> is NOT a void element — it requires a closing tag (</textarea>). Any text placed between the opening and closing tag becomes the initial default content.

Code Example 5: Grouping with <fieldset> and <legend>

For long forms, group related fields together for accessibility:

html
<fieldset>
  <legend>Shipping Address Details</legend>

  <label for="street">Street Address:</label>
  <input type="text" id="street" name="street">

  <label for="city">City:</label>
  <input type="text" id="city" name="city">
</fieldset>
Accessibility Advantage: When a screen reader enters the fieldset, it announces the <legend> title, so users always know which section they are currently filling out.

Code Example 6: Reading Form Data in Modern JavaScript

Modern JavaScript has a native FormData API that reads all inputs in 2 lines of code:

javascript
const form = document.querySelector("form");

form.addEventListener("submit", function(event) {
  event.preventDefault(); // Stop page reload

  // Automatically extracts all inputs with name attributes
  const data = new FormData(this);

  // Convert to clean JavaScript object
  const formValues = Object.fromEntries(data.entries());
  console.log("Submitted Form Data:", formValues);
});
Pro Feature: new FormData(form) automatically collects every text field, checked radio, selected dropdown, and password with zero manual DOM queries.
⚠ Common Beginner Mistakes
  • Forgetting the name attribute: An input with id="email" but NO name="email" will NEVER be sent to the server when the form is submitted! Always provide both.
  • Not connecting labels with for: Writing <label>Name</label><input id="name"> does not connect them. The label must explicitly have for="name" matching the input's ID.
  • Default button behavior inside forms: Any <button> inside a form defaults to type="submit"! If you want a button that triggers a JavaScript modal or calculation without submitting the form, you MUST write <button type="button">.
💡 Pro Tips
  • Use the autocomplete attribute (e.g. autocomplete="email" or autocomplete="current-password") — this allows password managers like 1Password and Chrome to auto-fill securely.
  • Always add placeholder text to provide an example of expected formatting, but never rely on placeholders instead of visible <label> tags.
🔄 Quick Recap
  • <form action="url" method="POST"> wraps user input controls.
  • Always link <label for="id"> to <input id="id">.
  • Inputs MUST have a name attribute to submit data to the server.
  • Radio buttons must share the exact same name to be mutually exclusive.
  • <select> creates dropdowns; <textarea> creates multi-line text boxes.
  • Always specify type="button" for buttons that should not submit the form.

Practice Exercises

Exercise 1 (Easy): Connect a Label to an Input Easy

Connect this label to the input so that clicking the word "Username" focuses the typing cursor:

<label>Username:</label>
<input type="text" id="user-field">
Hint: Add the for attribute to the label.
Solution:
<label for="user-field">Username:</label><input type="text" id="user-field">
Exercise 2 (Medium): Fix Independent Radio Buttons Medium

A user can select both "Small" and "Large" at the same time in this broken t-shirt size selector. Fix it so only one size can be chosen:

<input type="radio" id="s" name="size_s"> Small
<input type="radio" id="l" name="size_l"> Large
Hint: Radio buttons must share the exact same name value.
Solution: Give both radios the exact same name (e.g. name="tshirt_size"):
<input type="radio" id="s" name="tshirt_size" value="S"> Small
<input type="radio" id="l" name="tshirt_size" value="L"> Large
Exercise 3 (Hard): Prevent Accidental Form Submission Hard

Inside a form, a developer creates <button onclick="calculateTip()">Calculate</button>. Whenever users click it, the whole page refreshes and reloads. Why, and how do you fix it?

Hint: What is the default type of a button tag inside a form?
Solution: Any button inside a form defaults to type="submit", which triggers form submission and reloads the page! To prevent this, explicitly declare type="button":
<button type="button" onclick="calculateTip()">Calculate</button>
