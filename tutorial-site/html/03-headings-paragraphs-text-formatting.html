Headings, Paragraphs & Text Formatting

Structure content with proper typographic hierarchy and semantic emphasis tags. Content ko sahi heading hierarchy (h1 se h6) aur semantic text formatting tags ke saath organize karna seekhein.

📚 What You Will Learn
  • The strict hierarchy of headings from <h1> down to <h6>.
  • Paragraph handling, whitespace collapsing, and when to use <br> vs <hr>.
  • Semantic importance: <strong> vs <b>, and <em> vs <i>.
  • Special text markup: <mark>, <small>, <sub>, <sup>, <del>, and <ins>.
  • Displaying code with <code> and preserving whitespace with <pre>.
  • Quoting text using <blockquote> and inline <q>.
Prerequisites: Completion of 02. Elements & Attributes.
🌟 Real-Life Analogy: The Front Page of a Printed Newspaper

Open a physical newspaper. You instantly know what the biggest story of the day is because it has a massive, bold front-page Headline (<h1>). Major sections like "Sports" or "Business" use Section Titles (<h2>). Individual article titles use Subheads (<h3>). The stories themselves are broken into readable chunks called Paragraphs (<p>), with pull-quotes in larger italics. If every word in the newspaper was the same size, it would be an unreadable wall of gray! Ek akhbar (newspaper) ki tarah sochiye. Sabse badi khabar ka bada bold headline hota hai (<h1>), sections ke alag title hote hain (<h2>), aur har khabar chhote paragraphs mein bati hoti hai. Typographic hierarchy padhne wale ko guide karti hai.

1. The Heading Hierarchy (h1 through h6)

HTML offers 6 levels of headings. They indicate the structural importance of the sections that follow them, not merely their visual font size:

Code Example 1: Proper Heading Hierarchy

html
<h1>Modern Web Development Architecture</h1>   <!-- Top-level page topic (Only 1 per page) -->

  <h2>Frontend Technologies</h2>               <!-- Major Chapter / Section -->
    <h3>HTML5 Fundamentals</h3>                <!-- Sub-topic inside Frontend -->
      <h4>Document Skeletons</h4>              <!-- Detail inside HTML5 -->
      <h4>Semantic Tags</h4>

    <h3>CSS3 Styling</h3>                      <!-- Sibling sub-topic -->
      <h4>Flexbox Layouts</h4>

  <h2>Backend Systems</h2>                     <!-- Sibling Major Section -->
    <h3>Databases and APIs</h3>
The Golden Hierarchy Rule: Never skip heading levels for visual convenience! Do not jump from an <h2> straight to an <h4> just because you want smaller text. Use CSS to change font size; use HTML to define semantic structure.

2. Paragraphs and Whitespace Collapsing

Browsers collapse multiple consecutive spaces, tabs, and line breaks into a single space. To create separate paragraphs, you must wrap each block of prose in a <p> tag:

Code Example 2: Whitespace Collapsing in Action

html
<!-- The browser renders all these spaces and line breaks as ONE single space! -->
<p>
  This        is      a
  single
  paragraph.
</p>

<!-- To start a new paragraph with margin spacing, use a new <p> tag: -->
<p>This is the second distinct paragraph.</p>
Takeaway: Pressing Enter in your code editor 10 times does not create 10 empty lines on the webpage. If you genuinely need a manual line break within a postal address or poem, use the void element <br>.

3. Semantic Formatting: strong vs b, and em vs i

In early HTML, <b> meant "bold" and <i> meant "italic". In modern HTML5, we use semantic tags that convey meaning to screen readers:

Code Example 3: Visual Styling vs Semantic Meaning

html
<!-- 1. <strong>: High importance or serious urgency -->
<p><strong>Warning:</strong> Do not touch high-voltage wires.</p>

<!-- 2. <b>: Stylistic offset without extra importance (product names, keywords) -->
<p>The <b>MacBook Pro</b> features a retina display.</p>

<!-- 3. <em>: Stressed emphasis (changes sentence meaning when spoken aloud) -->
<p>I <em>really</em> love vanilla JavaScript.</p>

<!-- 4. <i>: Alternate voice or mood (foreign terms, book titles, thoughts) -->
<p>The phrase <i>carpe diem</i> is Latin for seize the day.</p>
Screen Reader Impact: Screen readers announce <strong> in an elevated, urgent tone, and <em> with vocal stress. Plain <b> and <i> are read in normal monotone.

Code Example 4: Editorial & Scientific Formatting Tags

html
<!-- Subscript (sub) & Superscript (sup) -->
<p>Glucose is C<sub>6</sub>H<sub>12</sub>O<sub>6</sub></p>
<p>The Pythagorean theorem: a<sup>2</sup> + b<sup>2</sup> = c<sup>2</sup></p>

<!-- Marked (highlighted) text -->
<p>Search results: We found 3 matches for <mark>responsive grid</mark>.</p>

<!-- Deletions and Insertions (Audit trails / changelogs) -->
<p>The meeting is on <del>Tuesday</del> <ins>Thursday</ins> at 10 AM.</p>

<!-- Small print (disclaimers, legal notices) -->
<p><small>© 2026 WebDev Academy. Terms and conditions apply.</small></p>
Key Benefit: These native tags provide immediate, accessible browser styles out of the box without requiring custom CSS rules.

Code Example 5: Presenting Computer Code with <code> and <pre>

When teaching coding, you need to display code snippets without the browser parsing them as live HTML:

html
<!-- Inline code snippet inside prose -->
<p>Use the <code>console.log()</code> method to print diagnostic text.</p>

<!-- Multi-line preformatted code block: preserves spaces and linebreaks exactly! -->
<pre><code>function greet(name) {
  return "Hello, " + name + "!";
}</code></pre>
How <pre> works: Unlike normal elements that collapse whitespace, <pre> preserves every space, tab, and newline exactly as written in the source code in a monospaced font.

Code Example 6: Blockquotes vs Inline Quotes

html
<!-- Extended quotation set apart as a separate indented block -->
<blockquote cite="https://www.w3.org">
  <p>The power of the Web is in its universality. Access by everyone regardless of disability is an essential aspect.</p>
  <footer>— Tim Berners-Lee, <cite>W3C Founder</cite></footer>
</blockquote>

<!-- Short inline quote: browser automatically inserts quotation marks -->
<p>As my mentor always said, <q>Practice code every single day.</q></p>
Pro Feature: The <q> tag automatically adds correct opening and closing quotation marks (localized by the lang attribute), so you don't type quote characters manually!
⚠ Common Beginner Mistakes
  • Using multiple <h1> tags: A page should almost always have exactly ONE <h1> describing the entire document. Multiple h1s confuse screen readers and dilute SEO ranking.
  • Using headings just to get big text: Never use <h1> just to make a warning banner big. Use a <p class="large-text"> and style it with CSS. Headings are an outline, not a font-size slider.
  • Using multiple <br><br><br> to create vertical space: Never use line break tags for layout spacing! Use CSS margins or padding. <br> is strictly for line breaks within a single sentence (like a street address).
💡 Pro Tips
  • Think of your headings like the Table of Contents of a book. If you extracted only your h1, h2, and h3 tags into a list, it should make complete, logical sense on its own.
  • Use <hr> to represent a thematic break (e.g., a shift in topic or scene change in a story), not merely as a decorative line.
🔄 Quick Recap
  • <h1> through <h6> define structural content hierarchy (one <h1> per page).
  • HTML collapses whitespace; use separate <p> tags for distinct paragraphs.
  • <strong> indicates urgent importance; <em> indicates spoken stress.
  • <sub> is subscript (H2O); <sup> is superscript (x2).
  • <pre> preserves whitespace; <code> denotes computer code.

Practice Exercises

Exercise 1 (Easy): Scientific Formula Markup Easy

Write the HTML snippet to display Carbon Dioxide as CO2 with the "2" as a subscript.

Hint: Use the sub tag for subscript numbers.
Solution: <p>CO<sub>2</sub></p>
Exercise 2 (Medium): Heading Audit Medium

Find the semantic flaw in this outline: <h1>Cooking</h1> → <h3>Desserts</h3> → <h2>Baking Tips</h2>.

Hint: Notice the level jump from h1 directly to h3 without an h2.
Solution: It skips level 2 (jumping from <h1> directly to <h3>), and then places an <h2> after an <h3>. The correct hierarchy should be:
<h1>Cooking</h1> → <h2>Desserts</h2> → <h3>Baking Tips</h3>.
Exercise 3 (Hard): Code Snippet Formatting Hard

How do you format a multi-line JavaScript function so that both indentation is preserved and screen readers identify it as programming code?

Hint: Nest code inside pre.
Solution: Wrap <code> inside a <pre> container:
<pre><code>function add(a, b) {
  return a + b;
}</code></pre>
