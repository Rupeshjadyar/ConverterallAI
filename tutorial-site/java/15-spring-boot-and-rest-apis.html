2. Technical Deep-Dive & Architecture

1. What Happens Inside `@SpringBootApplication`?

A meta-annotation combining three critical Spring annotations:

  • @SpringBootConfiguration: Declares the class as a primary source of Spring Bean definitions.
  • @EnableAutoConfiguration: Scans the classpath (e.g. finds spring-boot-starter-web) and automatically registers embedded Tomcat, Jackson JSON serializer, and DispatcherServlet.
  • @ComponentScan: Recursively scans packages below this class for @Component, @Service, @Repository, @RestController.

2. Complete REST Controller Pattern with DTO

@RestController
@RequestMapping("/api/v1/users")
public class UserController {
    private final UserService userService;

    public UserController(UserService userService) {
        this.userService = userService;
    }

    @PostMapping
    public ResponseEntity createUser(@Valid @RequestBody CreateUserRequestDTO request) {
        UserResponseDTO created = userService.registerUser(request);
        return ResponseEntity.status(HttpStatus.CREATED).body(created); // Returns 201 Created
    }

    @GetMapping("/{id}")
    public ResponseEntity getUserById(@PathVariable Long id) {
        return ResponseEntity.ok(userService.getUserById(id));          // Returns 200 OK
    }
}

3. Global Exception Handling with `@RestControllerAdvice`

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity> handleNotFound(ResourceNotFoundException ex) {
        Map error = new HashMap<>();
        error.put("timestamp", LocalDateTime.now());
        error.put("status", HttpStatus.NOT_FOUND.value());
        error.put("error", ex.getMessage());
        return ResponseEntity.status(HttpStatus.NOT_FOUND).body(error);
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity> handleValidation(MethodArgumentNotValidException ex) {
        Map errors = new HashMap<>();
        ex.getBindingResult().getFieldErrors().forEach(err -> 
            errors.put(err.getField(), err.getDefaultMessage()));
        return ResponseEntity.badRequest().body(errors); // Returns 400 Bad Request
    }
}

3. 🎙️ How to Answer in an Interview (Point-Wise Speaking Notes)

When the interviewer asks "How does Spring Boot Auto-Configuration work? What is the difference between @Controller and @RestController?", deliver these punchy technical bullet points without stammering:

  • Auto-Configuration Mechanism: Spring Boot inspects classes present on the classpath using `@ConditionalOnClass` and `@ConditionalOnMissingBean`. If Tomcat and Spring MVC jars are detected, Spring Boot automatically configures DispatcherServlet and starts an embedded servlet container without any manual XML or Java configuration.
  • @Controller vs @RestController: `@Controller` is traditional Spring MVC for server-side rendering (returns view template names like "index.html"). `@RestController` is a convenience meta-annotation that combines `@Controller` and `@ResponseBody`, instructing Spring to serialize method return objects directly into JSON/XML HTTP response bodies using Jackson.
  • DTO Pattern Necessity: Entities should not be exposed directly through REST endpoints because: 1) Leaks internal DB schema; 2) Exposes sensitive fields (passwords, internal IDs); 3) Causes Jackson serialization recursion cycles on bidirectional JPA relationships.
  • Centralized Error Handling: `@RestControllerAdvice` intercepts exceptions thrown anywhere across the controller layer and maps them to clean, consistent HTTP response envelopes (ProblemDetails / RFC 7807).
💡 Interview Golden Rule: State: "@RestController is @Controller + @ResponseBody. Spring Boot Auto-Configuration uses conditional annotations to configure beans automatically based on classpath starters."

package com.academy.dto;

import jakarta.validation.constraints.*;

public record CreateUserRequestDTO(
    @NotBlank(message = "Username is mandatory")
    @Size(min = 3, max = 50, message = "Username must be between 3 and 50 characters")
    String username,

    @NotBlank(message = "Email is mandatory")
    @Email(message = "Must be a valid email format")
    String email,

    @Min(value = 18, message = "User must be at least 18 years old")
    int age
) {}

6. ⚠️ Common Mistakes & Senior Architect Tips

❌ Common Rookie Mistakes

  • Returning Database Entities Directly from Controllers: Exposes internal database schema and triggers serialization cycles or accidental mass-assignment security vulnerabilities.
  • Omitting `@Valid` on `@RequestBody`: Without `@Valid`, annotations like `@NotNull` and `@Email` on your DTO are completely ignored by Spring, allowing invalid data into the database!
  • Placing Main Class in Wrong Package: If `@SpringBootApplication` is placed in `com.app.config`, `@ComponentScan` will never scan controllers located in `com.app.controller`!

🚀 Senior Developer Pro-Tips

  • Use Java Records for DTOs: Java 17+ `record` creates immutable DTOs with constructor, getters, equals, and hashCode in one single line of code.
  • Standardize Error Envelopes with RFC 7807: Spring Boot 3 natively supports `ProblemDetail.forStatusAndDetail()` for standardized API error contracts across all microservices.
  • Set Explicit HTTP Status Codes: Always return 201 Created on POST, 204 No Content on DELETE, and 404 Not Found on missing resources.

7. 🧠 Quick Recap (Revision Cheatsheet)

  • @SpringBootApplication enables auto-configuration and component scanning.: No XML required.
  • @RestController serializes return objects into JSON via Jackson.: Combines @Controller and @ResponseBody.
  • Jakarta Validation (@Valid, @NotNull, @Email): validates request DTOs at the controller gate.
  • @RestControllerAdvice centralizes error responses: into clean, consistent HTTP payloads.
