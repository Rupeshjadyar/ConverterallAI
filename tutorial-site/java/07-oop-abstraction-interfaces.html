1. Real-World Analogy (10th-Grade Explanations)

The Government USB-C Standard & The Half-Built Car Analogy

Interface (A Pure Legal Contract): Think of the European Union's USB-C law. The law does not make phone batteries or chips; it simply states: "Any phone sold in Europe MUST have a port that fits this exact 24-pin shape and supports 5 Volts." Apple, Samsung, and Google can build whatever internals they want, as long as they implement that exact USB-C contract!

Abstract Class (A Half-Built Car Chassis): An automaker builds an engine, 4 wheels, and a chassis on the assembly line (shared concrete code). But they leave the seats and badges off (abstract methods). The luxury division extends that chassis to put in leather seats; the budget division puts in fabric seats.

Interface (एक सरकारी नियम): आपके घर की दीवार में जो 3-पिन वाला बिजली का सॉकेट है, वह एक Interface है। सॉकेट को फर्क नहीं पड़ता कि आप उसमें फ्रिज लगा रहे हैं, पंखा लगा रहे हैं या मोबाइल चार्जर। जब तक आपके प्लग में 3 पिन हैं (Contract पूरा है), बिजली चालू हो जाएगी!

2. Default Methods & Diamond Conflict Resolution

If a class implements two interfaces that provide the same default method signature, the compiler forces you to override and disambiguate:

interface Printer {
    default void log() { System.out.println("Printer log"); }
}

interface Scanner {
    default void log() { System.out.println("Scanner log"); }
}

class AllInOneMachine implements Printer, Scanner {
    @Override
    public void log() {
        // Disambiguate which parent default method to invoke
        Printer.super.log(); 
    }
}

3. Java 17 Sealed Classes (`sealed` & `permits`)

In older Java, a class was either wide open for anyone to inherit, or final (closed to everyone). Java 17 introduces Sealed Classes, giving you fine-grained control over exactly which classes can extend your hierarchy:

// Only Circle, Square, and Triangle can extend Shape!
public sealed class Shape permits Circle, Square, Triangle {
}

public final class Circle extends Shape {}
public final class Square extends Shape {}
public non-sealed class Triangle extends Shape {} // Triangle re-opens for extension

3. 🎙️ How to Answer in an Interview (Point-Wise Speaking Notes)

When the interviewer asks "Why were default methods introduced in Java 8 interfaces? How do Sealed Classes improve domain modeling in Java 17?", deliver these punchy technical bullet points without stammering:

  • Interface Evolution & Backward Compatibility: Prior to Java 8, adding a new method to an existing interface broke all implementing classes. Default methods allowed the Java team to add `stream()` and `forEach()` to the Collection interface without breaking billions of lines of legacy code.
  • Functional Interfaces (SAM): An interface with exactly one abstract method is a Functional Interface (`@FunctionalInterface`), making it eligible to be instantiated via modern Lambda expressions and Method References.
  • Sealed Classes in Java 17: Sealed classes allow a superclass to declare a finite, exhaustive list of permitted subclasses. This empowers compile-time exhaustiveness checking in modern pattern matching switch expressions.
💡 Interview Golden Rule: State: "Default methods enable backward-compatible interface evolution. Sealed classes restrict inheritance to a known set of subclasses, creating secure, closed algebraic domain types."

4. Practical Code Examples (Step-by-Step)

Every line is crafted with industry best practices and enterprise design standards:

Example 1: Complete Interface Design with Default and Static Methods

public interface AuditableRepository {
    // Abstract method (Contract)
    void save(T entity);

    // Default method (Provided implementation)
    default void saveWithAudit(T entity) {
        System.out.println("[AUDIT] Timestamp: " + System.currentTimeMillis());
        save(entity);
    }

    // Static utility method
    static boolean isValidId(Long id) {
        return id != null && id > 0;
    }
}

Example 2: Java 17 Sealed Class Hierarchy with Pattern Matching Switch

public sealed interface ApiResponse permits SuccessResponse, ErrorResponse {}

public record SuccessResponse(String data) implements ApiResponse {}
public record ErrorResponse(int errorCode, String message) implements ApiResponse {}

public class ResponseHandler {
    public static String handle(ApiResponse response) {
        // Compiler knows ONLY SuccessResponse and ErrorResponse exist! No default needed!
        return switch (response) {
            case SuccessResponse s -> "200 OK: " + s.data();
            case ErrorResponse e   -> "Error " + e.errorCode() + ": " + e.message();
        };
    }
}

6. ⚠️ Common Mistakes & Senior Architect Tips

❌ Common Rookie Mistakes

  • Attempting to Instantiate an Abstract Class or Interface: Writing `new Shape()` fails compilation because abstract types have incomplete contracts.
  • Declaring Non-Final Instance Variables in Interfaces: All variables declared in interfaces are implicitly `public static final`. Attempting to treat them as mutable instance variables fails.
  • Creating Unnecessary Abstract Classes: Using an abstract class where an interface suffices limits the implementing class to single inheritance unnecessarily.

🚀 Senior Developer Pro-Tips

  • Program to Interfaces, Not Implementations: Declare `List list = new ArrayList<>()` instead of `ArrayList list`. This decouples your code and allows swapping implementations effortlessly.
  • Use `@FunctionalInterface` Everywhere Applicable: Annotating SAM interfaces enables the compiler to prevent accidental addition of a second abstract method.
  • Leverage Java 17 Records with Sealed Interfaces: Records implement sealed interfaces with zero boilerplate, providing immutable Domain-Driven Data Transfer Objects (DTOs).

7. 🧠 Quick Recap (Revision Cheatsheet)

  • Interfaces specify "what" to do;: classes specify "how" to do it.
  • Java 8 added `default` and `static` methods to interfaces: for backward compatibility.
  • Functional Interfaces have exactly 1 abstract method: and work seamlessly with Lambdas.
  • Java 17 Sealed Classes control inheritance: using `sealed` and `permits`.

Two interfaces A and B provide default method show(). Write class C implementing both and resolving the clash.

Show Solution 
class C implements A, B {
    @Override
    public void show() {
        A.super.show(); // Explicitly calls A's default method
    }
}

Exercise 3 (Hard): Sealed Hierarchy Subclass Rules

What three modifier keywords must any class that extends a sealed class choose from?

Show Solution

Solution: A permitted subclass of a sealed class MUST be declared as one of: final (cannot be extended further), sealed (continues sealing with its own permits list), or non-sealed (re-opens for unbounded inheritance).
