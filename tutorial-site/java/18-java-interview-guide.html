2. Technical Deep-Dive & Architecture

1. Core Java Master Q&A (Top 20 Critical Questions)

Q1: Why is Java not 100% pure Object-Oriented?

Answer: Java supports 8 primitive data types (int, boolean, char, etc.) which are not objects and do not inherit from java.lang.Object. However, Wrapper classes and Autoboxing bridge this gap.

Q2: What is the difference between `==` and `.equals()`?

Answer: == compares memory reference addresses (whether both pointers reference the identical Heap object). .equals() evaluates logical content equality (can be customized by overriding the method).

Q3: Why can't we override static or private methods?

Answer: Static methods are bound at compile-time to the class type (Static Binding), resulting in Method Hiding rather than dynamic virtual dispatch. Private methods are invisible to subclasses and bound privately at compile-time.

Q4: What is the contract between `hashCode()` and `equals()`?

Answer: 1) If two objects are equal according to equals(), their hashCode() MUST return the exact same integer. 2) If two objects have the same hashCode, they are NOT required to be equal (Hash Collision).

Q5: What is the difference between `fail-fast` and `fail-safe` iterators?

Answer: fail-fast iterators (e.g. ArrayList, HashMap) throw ConcurrentModificationException immediately upon detecting structural modifications using an internal modCount. fail-safe iterators (e.g. CopyOnWriteArrayList, ConcurrentHashMap) operate on a cloned snapshot without throwing exceptions.

2. Concurrency & JVM Tuning (Top Questions)

Q6: What is the Java Memory Model (JMM) happens-before relationship?

Answer: A formal specification guaranteeing that memory writes by one thread are visibly observable to reads by another thread (e.g., unlocking a monitor happens-before any subsequent lock of the same monitor; writing a volatile variable happens-before any subsequent read of that variable).

Q7: What are key JVM garbage collection tuning flags?

Answer: -Xms (Initial Heap size), -Xmx (Maximum Heap size), -XX:+UseG1GC (G1 Garbage Collector), -XX:+UseZGC (Ultra-low latency ZGC in Java 17/21 with sub-millisecond pauses), -XX:MaxMetaspaceSize.

3. Spring Boot & JPA Deep-Dive Questions

Q8: How does Spring AOP implement `@Transactional`?

Answer: Spring creates a dynamic CGLIB or JDK dynamic proxy around the bean. When the method is invoked, the proxy intercepts the call, opens a database connection transaction via PlatformTransactionManager, executes the target method, and automatically commits or rolls back upon catching an unchecked exception.

Q9: What happens if you call a `@Transactional` method from within the same class?

Answer: Self-invocation bypasses the proxy! Because the call goes through the internal this pointer rather than the Spring AOP proxy wrapper, the transaction interception logic is never executed!

3. 🎙️ How to Answer in an Interview (Point-Wise Speaking Notes)

When the interviewer asks "How do you diagnose and tune a Java application experiencing frequent OutOfMemoryError and high CPU spikes?", deliver these punchy technical bullet points without stammering:

  • Generate Heap & Thread Dumps: Configure `-XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/dumps` to capture heap snapshots automatically upon crash. Trigger thread dumps using `jcmd Thread.print` or `jstack`.
  • Analyze with Memory Profilers: Open the heap dump in Eclipse MAT (Memory Analyzer Tool) or JProfiler. Identify the Dominator Tree to see which class or collection retains the largest percentage of heap memory (e.g. unbounded cache).
  • CPU Spike Investigation: Find top CPU-consuming OS threads using `top -H -p `. Convert the thread ID to hexadecimal, and search for that nid in the thread dump to locate the exact infinite loop or lock contention.
  • Garbage Collector Optimization: Switch to G1GC or ZGC (`-XX:+UseZGC`) and tune pause time goals (`-XX:MaxGCPauseMillis=200`).
💡 Interview Golden Rule: Always state: "Diagnose production JVM issues by capturing heap dumps on crash, analyzing the dominator tree in Eclipse MAT for memory leaks, and mapping thread CPU spikes via jstack thread dumps."

The Classic Singleton Pattern (Thread-Safe Double-Checked Locking)

public class DatabaseConnectionPool {
    // volatile is MANDATORY to prevent instruction reordering!
    private static volatile DatabaseConnectionPool instance;

    private DatabaseConnectionPool() {
        // Guard against reflection instantiation
        if (instance != null) {
            throw new IllegalStateException("Singleton already initialized!");
        }
    }

    public static DatabaseConnectionPool getInstance() {
        if (instance == null) { // 1st check (no lock overhead)
            synchronized (DatabaseConnectionPool.class) {
                if (instance == null) { // 2nd check (under lock)
                    instance = new DatabaseConnectionPool();
                }
            }
        }
        return instance;
    }
}

6. ⚠️ Common Mistakes & Senior Architect Tips

❌ Common Rookie Mistakes

  • Saying "Java is pass-by-reference for objects": Immediate red flag for interviewers! Always clarify: "Java is strictly pass-by-value; for objects, the reference pointer is copied by value."
  • Failing to mention `volatile` in Double-Checked Locking: Without `volatile`, the JVM may reorder object memory allocation and constructor initialization, exposing a half-initialized object to other threads!
  • Claiming `@Transactional` catches all exceptions by default: Spring `@Transactional` rolls back ONLY on unchecked exceptions (`RuntimeException` and `Error`) by default, NOT checked exceptions, unless specified via `@Transactional(rollbackFor = Exception.class)`.

🚀 Senior Developer Pro-Tips

  • Use the STAR Framework for Behavioral & Architecture Questions: Situation, Task, Action, Result. Quantify outcomes: "Reduced p99 latency by 60% by switching from EAGER to LAZY loading with JOIN FETCH."
  • Know Your Big-O Complexities: Be ready to state exact time and space complexity for ArrayList, LinkedList, HashMap, and TreeMap operations off the top of your head.
  • Highlight Clean Code & Design Patterns: Mention Builder, Factory, Strategy, and Circuit Breaker patterns naturally in your architectural explanations.

How does Java resolve default method collisions when a class implements two interfaces with identical method signatures?

Show Solution

Solution: The compiler throws a compile error demanding that the implementing class explicitly override the method and specify which interface implementation to call via InterfaceName.super.methodName().

How do you configure @Transactional to roll back when a checked IOException occurs?
