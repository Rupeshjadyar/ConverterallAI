1. Why Word Processors Ruin Code (Plain Text vs Rich Text)

You cannot write code in programs like Microsoft Word, Apple Pages, or Google Docs. Here is why:

  • Rich Text (Word, Docs): These programs inject invisible hidden metadata, font styling, formatting tables, margins, and "smart curly quotes" (like “ and ”). To a browser parser, curly quotes are invalid syntax errors that break your code!
  • Plain Text (.html, .css, .js): Code requires pure UTF-8 plain text with straight quotes (" and '). Code editors (such as VS Code, Sublime Text, or even built-in Windows Notepad) save pure characters without hidden formatting baggage.

Code Example 1: The Danger of "Smart" Curly Quotes vs Straight Quotes

html
<!-- BROKEN: Word processors replace quotes with curly quotation marks -->
<a href=“index.html” class=“button”>Click Me</a>  <!-- SYNTAX ERROR! -->

<!-- VALID: Plain text editors preserve straight quotes -->
<a href="index.html" class="button">Click Me</a>  <!-- CLEAN & VALID -->
Line-by-line Breakdown:
• Notice the curvature in “ and ”. A browser treats these as unrecognized Unicode symbols, destroying the attribute.
• The second example uses straight ASCII quotes (", Unicode U+0022), which browsers parse flawlessly.

2. Critical Step: Show File Extensions

By default, both Windows and macOS hide file extensions (the letters after the dot, such as .txt or .html). This causes a notorious beginner trap: saving a file as index.html.txt without knowing it!

💡 How to Enable File Extensions in Windows
  1. Open File Explorer (press Windows Key + E).
  2. Click the View tab at the top.
  3. Look for the "File name extensions" checkbox and check it ON! (On Windows 11: View → Show → File name extensions).

Code Example 2: Standard Professional Project Folder Architecture

Every professional web project follows this predictable folder structure:

plaintext
my-web-project/
├── index.html            (Home page, always lower-case index.html)
├── about.html            (Secondary page)
├── contact.html          (Contact page)
├── css/
│   └── styles.css        (All styling rules)
├── js/
│   └── app.js            (All interactive JavaScript)
└── images/
    ├── logo.svg
    └── avatar.jpg
Why this structure matters:
• Web servers automatically serve index.html as the default landing file if no specific file is requested in the URL.
• Keeping CSS, JS, and images separated in their own subdirectories prevents your project from becoming an unmanageable mess.

Code Example 3: Essential VS Code Keyboard Shortcuts

Speed is everything when writing code. Commit these keyboard shortcuts to muscle memory:

plaintext
Ctrl + S (Cmd + S on Mac)      : Save current file (Do this constantly!)
Ctrl + / (Cmd + / on Mac)      : Comment / uncomment current line of code
Alt + Up / Down Arrow          : Move the current line up or down
Shift + Alt + Down Arrow       : Duplicate the current line downwards
Ctrl + ` (Backtick)            : Toggle built-in terminal console
Ctrl + F                       : Find text within file
Ctrl + Shift + F               : Find text across ALL files in the project folder
Key Takeaway: Professional developers rarely reach for their mouse. Keyboard shortcuts allow your hands to stay on the home row, keeping your train of thought uninterrupted.

Code Example 4: Emmet Abbreviation Boilerplate

In VS Code, you never have to type the basic HTML skeleton by hand. Type ! and press Tab:

html
<!-- Type ! and press Tab to generate this entire block in 0.1 seconds -->
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Document</title>
</head>
<body>

</body>
</html>
Line-by-line Breakdown:
• Emmet is built into VS Code by default with zero configuration.
• meta charset="UTF-8" ensures special symbols, emojis, and characters from all human languages render without gibberish.
• meta name="viewport" guarantees the page scales correctly on mobile phones.

Code Example 5: Testing Local File Paths (Relative References)

How an HTML file in your project folder links to sibling CSS and JS files without needing an internet server:

html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Offline Project</title>
  <!-- Notice the relative path starting with ./ or folder name -->
  <link rel="stylesheet" href="./css/styles.css">
</head>
<body>
  <h1>Local Development</h1>
  <img src="./images/logo.svg" alt="Project Logo">
  <script src="./js/app.js"></script>
</body>
</html>
Line-by-line Breakdown:
• ./ means "look in the current folder where this HTML file lives".
• ./css/styles.css directs the browser into the subfolder css to find styles.css.
• This ensures that your site functions 100% offline whether opened from a USB flash drive or a hard disk!

Code Example 6: Verifying Browser Offline Storage with Console

You can verify that your browser can store local settings even without an active internet connection:

javascript
// Run in browser console to test offline state persistence
localStorage.setItem("editor_preference", "VSCode");
localStorage.setItem("theme_preference", "Dark");

const preferredEditor = localStorage.getItem("editor_preference");
console.log("Configured Editor: " + preferredEditor);
console.log("Storage Working: " + (preferredEditor === "VSCode"));
Line-by-line Breakdown:
• localStorage.setItem(key, value) stores key-value pairs permanently on your machine.
• localStorage.getItem(key) retrieves the value even if you close and reopen the browser offline.
⚠ Common Beginner Mistakes
  • Spaces in file names: Never name files my cool page.html! Use hyphens: my-cool-page.html. Spaces turn into ugly %20 strings in URLs and break links.
  • Capital letters in file names: Always use lowercase (e.g. index.html, not Index.HTML). Windows is case-insensitive, but real Linux web servers are case-sensitive. Logo.PNG and logo.png are two different files on Linux!
  • Forgetting to save: In VS Code, a small solid white circle on the file tab means the file has unsaved changes. Always hit Ctrl + S before refreshing the browser.
💡 Pro Tips
  • Turn on Auto Save in VS Code (File → Auto Save) so you never lose code or wonder why your browser isn't updating!
  • Always create a dedicated folder for each project on your Desktop or Documents (e.g., portfolio-project/) before creating any files.
🔄 Quick Recap
  • Use a code editor like VS Code, not a word processor like Word.
  • Always enable "File name extensions" in your operating system.
  • Use lowercase, hyphenated file names with no spaces (my-page.html).
  • Keep assets organized in css/, js/, and images/ subfolders.
  • Use Ctrl+S to save and Ctrl+/ to toggle comments.

Practice Exercises

Exercise 1 (Easy): Identify the Valid Filename Easy

Which of the following is the best, production-safe filename for a contact page?

Hint: Remember the rule: lowercase, hyphens, no spaces, straight extension.
Solution: contact-us.html.
Avoid Contact Us.html (spaces and capitals) or contact_us.HTML (capital extension).
Exercise 2 (Medium): Relative File Navigation Medium

Your HTML file is at my-site/index.html. Your CSS file is at my-site/css/main.css. What exact href path must you put in the <link> tag?

Hint: Look from index.html into the css folder.
Solution: href="css/main.css" (or href="./css/main.css").
Exercise 3 (Hard): Spot the Bug in this Markup Hard

Examine this line of code: <link rel=“stylesheet” href=“styles.css”>. Why will this fail in a real browser?

Hint: Check the quotation marks closely!
Solution: It uses smart curly quotes (“ and ”) pasted from a word processor instead of straight ASCII quotes ("). The browser will fail to parse the attribute values correctly.
