🗣️ How to Speak in an Interview (Crisp Speaking Points)
  • What is Method Resolution Order (MRO)? The deterministic order in which Python searches for methods and attributes in a class hierarchy, especially during multiple inheritance. Python uses the C3 Linearization algorithm (accessible via ClassName.__mro__ or ClassName.mro()).
  • How does super() work? super() returns a proxy object that delegates method calls to the next class in the MRO chain, ensuring that parent initializers are called cooperatively without duplicate executions.
  • What is Duck Typing? 'If it walks like a duck and quacks like a duck, it's a duck.' Python checks for the presence of methods and behaviors at runtime, rather than requiring rigid type casting or explicit interface declarations.
  • What is an Abstract Base Class (ABC)? A class that cannot be instantiated directly and serves as a formal contract. Any subclass MUST implement all methods decorated with @abstractmethod, or Python will raise a TypeError at instantiation time.
  • Composition over Inheritance: Senior software design principle: prefer building complex objects by combining independent components ('has-a' relationship) rather than creating deeply nested inheritance trees ('is-a' relationship).

1. Single Inheritance & The super() Proxy

Inheritance allows a new class (subclass/child) to inherit attributes and methods from an existing class (base/parent), promoting code reuse and establishing 'is-a' relationships.

When overriding a parent method, super() delegates execution to the parent class implementation, ensuring foundational state is initialized correctly.

2. Multiple Inheritance & The Diamond Problem (MRO)

Unlike Java, Python natively supports Multiple Inheritance: a class can inherit from two or more parent classes simultaneously.

To resolve the famous 'Diamond Problem' (where class D inherits from B and C, which both inherit from A), Python uses the mathematical C3 Linearization algorithm to establish a predictable Method Resolution Order (MRO).

3. Duck Typing & Abstract Base Classes (ABCs)

Python is fundamentally dynamic. Polymorphism in Python is expressed through Duck Typing: code doesn't care about an object's explicit class, only whether it has the required methods.

When building enterprise frameworks where strict contracts are required, the standard library abc module provides ABC and @abstractmethod to enforce implementations at compile/instantiation time.

Practical Hands-On Code Demonstrations

Code Example 1: Single Inheritance and super() Constructor Delegation

python
class Employee:
    def __init__(self, name: str, employee_id: int, base_salary: float) -> None:
        self.name = name
        self.employee_id = employee_id
        self.base_salary = base_salary

    def calculate_pay(self) -> float:
        return self.base_salary

# Manager inherits from Employee (Manager IS AN Employee)
class Manager(Employee):
    def __init__(self, name: str, employee_id: int, base_salary: float, bonus: float) -> None:
        # Call parent constructor using super()
        super().__init__(name, employee_id, base_salary)
        self.bonus = bonus

    # Override parent method to include management bonus
    def calculate_pay(self) -> float:
        return super().calculate_pay() + self.bonus

m = Manager('Priya Verma', 101, 95000.0, 20000.0)
print(f'{m.name} Total Pay: ${m.calculate_pay():.2f}')  # $115,000.00
• super().__init__() ensures parent attributes are initialized before child-specific attributes are added.

Code Example 2: Multiple Inheritance and Inspecting the MRO Chain

python
class Loggable:
    def log(self, msg: str) -> None:
        print(f'[AUDIT LOG]: {msg}')

class Serializable:
    def to_dict(self) -> dict:
        return self.__dict__

# UserEntity inherits from TWO parent classes simultaneously
class UserEntity(Loggable, Serializable):
    def __init__(self, username: str, role: str) -> None:
        self.username = username
        self.role = role

u = UserEntity('aarav_dev', 'admin')
u.log('User signed in')
print(f'Serialized Dictionary: {u.to_dict()}')

# Inspect the Method Resolution Order (MRO)
print(f'MRO Chain: {[cls.__name__ for cls in UserEntity.__mro__]}')
• UserEntity.__mro__ reveals the exact sequence Python uses to locate methods across parent classes.

Code Example 3: Polymorphism in Action: Processing Heterogeneous Objects

python
class StripeGateway:
    def process_payment(self, amount: float) -> str:
        return f'Stripe: Processed card payment of ${amount:.2f}'

class PayPalGateway:
    def process_payment(self, amount: float) -> str:
        return f'PayPal: Redirected user for checkout of ${amount:.2f}'

class CryptoGateway:
    def process_payment(self, amount: float) -> str:
        return f'Crypto: Broadcasted transfer of ${amount:.2f} to blockchain'

# Polymorphic checkout processor: Works on ANY gateway with .process_payment()!
def execute_checkout(gateway, amount: float) -> None:
    print(gateway.process_payment(amount))

gateways = [StripeGateway(), PayPalGateway(), CryptoGateway()]
for gw in gateways:
    execute_checkout(gw, 150.00)
• execute_checkout demonstrates Duck Typing: it doesn't care what class the gateway belongs to, as long as it has a process_payment() method!

Code Example 4: Abstract Base Classes (ABCs) Enforcing Contracts

python
from abc import ABC, abstractmethod

class DatabaseConnector(ABC):
    """Abstract base interface: cannot be instantiated directly."""

    @abstractmethod
    def connect(self) -> None:
        pass

    @abstractmethod
    def execute_query(self, query: str) -> list:
        pass

class PostgresConnector(DatabaseConnector):
    def connect(self) -> None:
        print('Connected to PostgreSQL on port 5432')

    def execute_query(self, query: str) -> list:
        return [{'status': 'success', 'query': query}]

# Instantiating concrete subclass works:
pg = PostgresConnector()
pg.connect()

# Trying to instantiate abstract class raises TypeError!
try:
    invalid = DatabaseConnector()
except TypeError as err:
    print(f'Caught ABC enforcement: {err}')
• Abstract Base Classes guarantee that all subclasses implement required architectural interfaces.

Code Example 5: Checking Types with isinstance() and issubclass()

python
print(f'Is Manager an Employee subclass? {issubclass(Manager, Employee)}')  # True
print(f'Is m an instance of Employee? {isinstance(m, Employee)}')             # True
print(f'Is m an instance of object? {isinstance(m, object)}')                 # True (All classes inherit from object!)
• In Python, every class ultimately inherits from the root object base class.

Code Example 6: Composition Over Inheritance (The Pro Pattern)

python
class Engine:
    def start(self) -> str:
        return 'V8 Engine roaring to life!'

class GPS:
    def navigate(self) -> str:
        return 'GPS: Route plotted to destination.'

# Car HAS AN Engine and HAS A GPS (Composition)
class Car:
    def __init__(self) -> None:
        self.engine = Engine()
        self.gps = GPS()

    def drive(self) -> None:
        print(self.engine.start())
        print(self.gps.navigate())
        print('Car is rolling forward smoothly.')

c = Car()
c.drive()
• Composition decouples classes and avoids rigid, fragile inheritance hierarchies.

⚠️ Common Beginner & Production Mistakes
  • Hardcoding parent class names instead of using super(): Writing Employee.__init__(self, ...) breaks cooperative multiple inheritance. Always use super().__init__(...).
  • Creating deep, fragile inheritance trees: Hierarchies 5 or 6 levels deep become impossible to maintain. Favour composition over deep inheritance.
  • Forgetting to implement abstract methods: Forgetting even one @abstractmethod in a subclass prevents that subclass from being instantiated.
💡 Senior Python Engineer Pro Tips
  • Check MRO before debugging multiple inheritance: Always print ClassName.__mro__ if a method call in multiple inheritance behaves unexpectedly.
  • Use Mixins for reusable behavior: Mixin classes (like JsonMixin or LoggingMixin) provide small chunks of modular functionality without complex state.
⚑ Quick Recap & Key Takeaways
  • Inheritance promotes code reuse via 'is-a' relationships.
  • super() delegates to parent classes via the Method Resolution Order (MRO).
  • MRO is calculated using the C3 Linearization algorithm.
  • Duck Typing checks behavior rather than explicit class type.
  • Abstract Base Classes (abc.ABC) enforce interface contracts at instantiation.
