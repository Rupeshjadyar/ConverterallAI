🗣️ How to Speak in an Interview (Crisp Speaking Points)
  • What is the purpose of if __name__ == '__main__'? When a Python file is executed directly from the terminal (python script.py), the interpreter assigns the special built-in variable __name__ = '__main__'. When that same file is imported by another module (import script), __name__ is set to the module's actual filename ('script'). This allows a file to serve as both an importable library and a standalone executable tool without running testing code on import!
  • How does Python locate modules during import? Python searches directories in sys.path in order: 1) The current working directory where the script was launched. 2) The PYTHONPATH environment variable. 3) Standard library directories. 4) The site-packages directory (where pip installs external packages).
  • What does __init__.py do? In Python 3.3+, namespace packages allow omitting __init__.py, but in professional production projects, __init__.py is still standard: it marks a directory as a regular Python package, initializes package-level state, and controls exports via __all__.
  • Circular Imports: When module A imports module B, and module B imports module A. At runtime, module B attempts to access attributes of module A before module A has finished initializing, raising an ImportError. Fix: Refactor shared logic into a module C or import inside function scope.
  • sys.modules cache: Python caches imported modules in the dictionary sys.modules. Re-importing a module in another file simply returns the cached object in memory without re-executing the file's top-level code.

1. Modules vs Packages: Structuring Python Projects

As software grows beyond a single file, organizing code becomes paramount:

• Module: Any single Python file (e.g. database.py) containing functions, classes, and variables.
• Package: A directory containing multiple modules and an __init__.py file, allowing dot-notation imports: from app.services.auth import verify_password.

2. The Golden Idiom: if __name__ == '__main__'

Every Python developer sees this boilerplate on line 1 of script entrypoints:

Whenever you import a file, Python executes all top-level statements in that file from top to bottom. Wrapping test or launch code inside if __name__ == '__main__': guarantees it runs ONLY when explicitly invoked from the terminal.

3. Dependency Management: pip & requirements.txt

In enterprise development, projects depend on external libraries from the Python Package Index (PyPI) such as requests, fastapi, or pandas.

We track explicit versions using pip freeze > requirements.txt and install them cleanly inside our virtual environment with pip install -r requirements.txt.

Practical Hands-On Code Demonstrations

Code Example 1: Demonstrating if __name__ == '__main__' Behavior

python
# File: math_calculator.py

def add(a: float, b: float) -> float:
    return a + b

def multiply(a: float, b: float) -> float:
    return a * b

# Code below runs ONLY when run directly: python math_calculator.py
# It will NOT run when another file does: import math_calculator
if __name__ == '__main__':
    print('Running standalone self-tests...')
    assert add(2, 3) == 5
    assert multiply(4, 5) == 20
    print('All unit tests passed successfully!')
• When imported by another file, only add and multiply are exposed; the test block remains inert.

Code Example 3: Package Initialization and Controlling Exports with __all__

python
# File: my_app/services/__init__.py
"""Package initializer controlling wildcard exports."""
from .auth import authenticate_user, generate_jwt_token
from .mailer import send_welcome_email

# Controls what 'from my_app.services import *' will expose
__all__ = ['authenticate_user', 'generate_jwt_token', 'send_welcome_email']
• __all__ explicitly defines the public API of a package, hiding private internal helpers.

Code Example 4: Inspecting sys.path and Module Search Resolution

python
import sys

print('Python Module Search Resolution Order:')
for idx, directory in enumerate(sys.path, 1):
    print(f'  {idx}. {directory}')
• sys.path displays the exact directory search order used by Python when resolving imports.

Code Example 5: Dynamic Module Importing with importlib

python
import importlib

# Dynamically load plugins or drivers at runtime
module_name = 'math'
math_lib = importlib.import_module(module_name)

print(f'Pi from dynamically loaded {module_name}: {math_lib.pi}')
print(f'Cosine of 0: {math_lib.cos(0)}')
• importlib.import_module() is the backbone of plugin architectures in modern Python frameworks.

⚠️ Common Beginner & Production Mistakes
  • Circular Imports: Having file A import file B, while file B imports file A. Fix by refactoring shared models into a separate models.py file.
  • Using wildcard imports (from module import *): Pollutes the local namespace, obscures where functions came from, and can silently overwrite built-in functions. Always import explicit symbols!
  • Naming a local script after a standard library module: Naming a file email.py or json.py shadows the standard library, breaking all imports of that library.
💡 Senior Python Engineer Pro Tips
  • Use pip-tools or Poetry: In production projects, use tools like poetry or pip-compile to generate lockfiles (poetry.lock) that guarantee 100% cryptographic reproducibility across all machines.
  • Relative imports in packages: Inside a package, use from . import sibling or from ..parent import helper to keep internal imports portable even if the root package is renamed.
⚑ Quick Recap & Key Takeaways
  • A module is a .py file; a package is a directory containing modules and an __init__.py file.
  • if __name__ == '__main__' allows files to act as both libraries and standalone executables.
  • Python searches sys.path to resolve imports and caches loaded modules in sys.modules.
  • Never use wildcard imports (from x import *); import explicit symbols.
  • Pin exact dependency versions in requirements.txt for production stability.
