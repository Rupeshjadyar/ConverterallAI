🗣️ How to Speak in an Interview (Crisp Speaking Points)
  • What is 'self' in Python? self represents the specific instance of the class. Unlike C++ or Java where this is an implicit keyword, Python makes self an explicit first parameter in instance methods to maintain the Zen of Python ('Explicit is better than implicit').
  • Instance Variable vs Class Variable:
    • Instance Variable: Defined inside methods (usually __init__) using self.var. Unique to each object instance.
    • Class Variable: Defined directly inside the class body. Shared across ALL instances of that class.
  • Instance Method vs @classmethod vs @staticmethod:
    • Instance Method: Receives self, can read/modify instance and class state.
    • @classmethod: Receives cls (the class itself), used for alternative factory constructors.
    • @staticmethod: Receives neither self nor cls. A plain utility function logically scoped inside a class.
  • Name Mangling (Private Attributes __): Python does not have strict private access modifiers. Prefixing with double underscores (e.g. __balance) triggers name mangling, renaming it internally to _ClassName__balance to prevent accidental subclass overrides.
  • Why use @property? It allows you to expose class attributes with clean attribute access syntax (obj.balance) while transparently intercepting reads and writes through validation methods (getters and setters).

1. What is a Class and an Object?

Object-Oriented Programming (OOP) is a programming paradigm that organizes code around data models called Objects rather than standalone functions and logic.

A Class is a user-defined prototype or blueprint from which objects are created. Classes bundle data attributes and functions (called methods) into cohesive units.

2. The __init__ Constructor & The Role of 'self'

When you instantiate a class (car = Car('Red', 85)), Python allocates memory for a new instance and automatically passes that instance to the __init__ initialization method as the first argument, conventionally named self.

Inside __init__, you attach attributes to the new object: self.color = color.

3. Encapsulation & Python Properties (@property)

In other languages, developers write verbose getter and setter methods like getBalance() and setBalance(val).

Python provides the @property decorator, allowing you to use clean attribute access syntax (account.balance = 500) while running underlying validation methods to enforce business constraints.

Code Example 1: Creating a Complete BankAccount Class with State & Methods

python
class BankAccount:
    """Represents a real-world commercial bank account."""
    
    # Class Variable: Shared by ALL bank accounts
    BANK_NAME = 'Apex Global Bank'
    INTEREST_RATE = 0.04

    def __init__(self, account_holder: str, initial_balance: float = 0.0) -> None:
        # Instance Variables: Unique to EACH individual account
        self.account_holder = account_holder
        self.balance = initial_balance

    def deposit(self, amount: float) -> None:
        if amount <= 0:
            raise ValueError('Deposit amount must be strictly positive.')
        self.balance += amount
        print(f'Deposited ${amount:.2f}. New balance: ${self.balance:.2f}')

    def withdraw(self, amount: float) -> None:
        if amount > self.balance:
            raise ValueError('Insufficient funds for withdrawal.')
        self.balance -= amount
        print(f'Withdrew ${amount:.2f}. Remaining balance: ${self.balance:.2f}')

# Instantiate two distinct account objects
acc1 = BankAccount('Aarav Sharma', 1000.00)
acc2 = BankAccount('Priya Verma', 250.00)

acc1.deposit(500.00)
print(f'{acc1.account_holder} has ${acc1.balance:.2f} at {BankAccount.BANK_NAME}')
print(f'{acc2.account_holder} has ${acc2.balance:.2f}')
• Notice how acc1 and acc2 maintain completely independent balances while sharing BANK_NAME.

Code Example 2: Instance Methods vs @classmethod vs @staticmethod

python
import json

class User:
    def __init__(self, username: str, email: str) -> None:
        self.username = username
        self.email = email

    # 1. Instance Method: Receives self, accesses instance data
    def get_info(self) -> str:
        return f'{self.username} <{self.email}>'

    # 2. Class Method: Receives cls, commonly used as alternative constructors
    @classmethod
    def from_json(cls, json_str: str):
        data = json.loads(json_str)
        return cls(data['username'], data['email'])

    # 3. Static Method: Plain utility function, receives neither self nor cls
    @staticmethod
    def is_valid_email(email: str) -> bool:
        return '@' in email and '.' in email

# Create via standard constructor
u1 = User('aarav', 'aarav@mail.com')

# Create via factory class method
u2 = User.from_json('{"username": "priya", "email": "priya@mail.com"}')

print(u2.get_info())
print(f'Is test@test.com valid? {User.is_valid_email("test@test.com")}')
• @classmethod acts as a factory constructor; @staticmethod groups utility logic inside the class namespace.

Code Example 3: Encapsulation with @property Getters and Setters

python
class Thermostat:
    def __init__(self, celsius: float) -> None:
        self._celsius = celsius  # Protected internal attribute

    @property
    def celsius(self) -> float:
        """Getter method for celsius temperature."""
        return self._celsius

    @celsius.setter
    def celsius(self, value: float) -> None:
        """Setter method enforcing physical absolute zero (-273.15C) validation."""
        if value < -273.15:
            raise ValueError('Temperature cannot fall below absolute zero (-273.15 C)!')
        self._celsius = value

    @property
    def fahrenheit(self) -> float:
        """Computed property calculated dynamically on read."""
        return (self._celsius * 9/5) + 32

t = Thermostat(25.0)
print(f'{t.celsius} C = {t.fahrenheit} F')  # Clean attribute read
t.celsius = 30.0                         # Clean attribute write with validation!
• @property provides elegant attribute syntax while enforcing validation rules behind the scenes.

Code Example 4: Name Mangling with Private Attributes (__)

python
class Vault:
    def __init__(self, secret_code: str) -> None:
        # Double underscore triggers private name mangling
        self.__secret_code = secret_code

v = Vault('SuperSecretKey123')

try:
    # Direct access fails with AttributeError!
    print(v.__secret_code)
except AttributeError:
    print('Direct access blocked by name mangling!')

# Python mangles the name to _ClassName__variableName
print(f'Mangled internal name: {v._Vault__secret_code}')
• Python mangles __var to _ClassName__var to prevent accidental overwrites in subclasses.

Code Example 5: Magic Methods: __str__ and __repr__

python
class Book:
    def __init__(self, title: str, author: str, pages: int) -> None:
        self.title = title
        self.author = author
        self.pages = pages

    def __str__(self) -> str:
        # Friendly string for end-users (used by print() and str())
        return f'"{self.title}" by {self.author}'

    def __repr__(self) -> str:
        # Unambiguous technical representation for developers/debugging
        return f'Book(title={self.title!r}, author={self.author!r}, pages={self.pages})'

b = Book('1984', 'George Orwell', 328)
print(str(b))   # User view: "1984" by George Orwell
print(repr(b))  # Developer view: Book(title='1984', author='George Orwell', pages=328)
• __str__ is for humans; __repr__ is for developers and debugging.

Code Example 6: Operator Overloading with __add__ and __eq__

python
class Vector2D:
    def __init__(self, x: float, y: float) -> None:
        self.x = x
        self.y = y

    def __add__(self, other):
        # Overloads the '+' operator!
        return Vector2D(self.x + other.x, self.y + other.y)

    def __eq__(self, other) -> bool:
        # Overloads the '==' operator!
        return self.x == other.x and self.y == other.y

    def __repr__(self) -> str:
        return f'Vector2D({self.x}, {self.y})'

v1 = Vector2D(2, 3)
v2 = Vector2D(5, 7)
v3 = v1 + v2  # Calls v1.__add__(v2)
print(f'Sum vector: {v3}')  # Vector2D(7, 10)
• Python allows your custom classes to seamlessly integrate with native arithmetic and comparison operators.

⚠️ Common Beginner & Production Mistakes
  • Forgetting self in method declarations: Writing def drive(): inside a class raises TypeError: drive() takes 0 positional arguments but 1 was given when called on an instance.
  • Mutating a class variable through an instance: Writing self.CLASS_VAR = 10 creates an instance variable that shadows the class variable, rather than modifying the shared class variable!
  • Confusing __str__ and __repr__: If you only implement one, implement __repr__ because Python falls back to __repr__ if __str__ is missing.
💡 Senior Python Engineer Pro Tips
  • dataclasses for boilerplate-free classes: In Python 3.7+, use @dataclass from the standard library to automatically generate __init__, __repr__, and __eq__ methods without boilerplate code!
  • Slots for memory optimization: In high-performance systems with millions of objects, define __slots__ = ('x', 'y') in your class to eliminate the internal instance __dict__, saving 40-50% RAM!
⚑ Quick Recap & Key Takeaways
  • Classes are blueprints; Objects are instances containing state and behavior.
  • self explicitly represents the current instance.
  • Instance variables are unique per object; Class variables are shared.
  • @property provides Pythonic getters and setters with transparent validation.
  • Double underscore (__) triggers name mangling for private attributes.

        return self._height

            raise ValueError('Height must be positive')
        self._height = val

        return self.width * self.height
