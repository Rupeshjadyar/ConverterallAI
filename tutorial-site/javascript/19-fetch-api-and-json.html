1. Understanding JSON (JavaScript Object Notation)

JSON is a lightweight, text-based data exchange format that is completely programming-language independent. While derived from JavaScript object literal syntax, JSON has much stricter formatting constraints: JSON ek universal plain-text format hai jo systems ke beech data transfer karne ke liye use hota hai. Yeh JavaScript object jaisa dikhta hai par iske niyam kaafi strict hote hain:

Grammar Rule JavaScript Object Literal Valid JSON
Keys / Property Names Quotes optional: { name: "Sam" } MUST be wrapped in double quotes: { "name": "Sam" }
String Literals Single quotes, double quotes, backticks Double quotes ONLY: "valid string"
Trailing Commas Allowed: [1, 2, 3,] Strictly Forbidden! [1, 2, 3]
Supported Data Types Functions, symbols, undefined, BigInt, Date Strings, Numbers, Booleans, null, Arrays, Objects ONLY
Comments // comment and /* ... */ Zero comments allowed!
JavaScript — JSON.stringify() and JSON.parse() 
// 1. A rich JavaScript in-memory Object
const devProfile = {
  id: 1042,
  name: "Vikram Malhotra",
  skills: ["HTML5", "CSS3", "JavaScript"],
  isActive: true,
  createdAt: new Date("2026-01-15T10:00:00Z"),
  internalToken: undefined // Notice: undefined is dropped in JSON!
};

// 2. Convert Object -> JSON String (Serialization)
// Arguments: (value, replacer, indentation spaces for pretty-print)
const jsonText = JSON.stringify(devProfile, null, 2);
console.log("JSON String Output:\n", jsonText);

// 3. Convert JSON String -> Live JavaScript Object (Deserialization)
const restoredObject = JSON.parse(jsonText);
console.log("Restored User Name:", restoredObject.name);
console.log("Skill Count:", restoredObject.skills.length); // 3

// Defensive Parsing: Always wrap JSON.parse in try...catch!
try {
  const badData = JSON.parse("{ malformed json }");
} catch (err) {
  console.warn("JSON Parse Error caught safely:", err.message);
}
Key Insights:
  • JSON.stringify(obj, null, 2) adds 2 spaces of human-readable indentations — excellent for debugging and logging.
  • undefined properties, functions, and symbols are automatically omitted during serialization.
  • Always wrap JSON.parse() inside a try...catch block because passing an invalid string throws a fatal SyntaxError!

2. HTTP Fundamentals for Frontend Developers

The Web communicates using the HTTP (Hypertext Transfer Protocol) request-response lifecycle. Every request sent by fetch() includes an HTTP method, a URL endpoint, headers, and an optional body: Client aur server HTTP protocol ke jariye baat karte hain. Har request me method, URL, headers aur data body hoti hai:

HTTP Method REST Intent Sends Body? Idempotent?
GET Retrieve/read data from server No Yes (calling 100 times doesn't mutate state)
POST Create a brand new record/resource Yes (JSON payload) No (calling 100 times creates 100 records)
PUT Replace an entire existing record Yes (Complete record) Yes
PATCH Update specific fields of a record Yes (Partial fields) No / Dependent
DELETE Remove/destroy a record Usually No Yes

Common HTTP Status Codes:

  • 200 OK: Request succeeded; returned data in body.
  • 201 Created: Record successfully created on server (typical POST response).
  • 400 Bad Request: Client sent invalid or missing payload data.
  • 401 Unauthorized: Missing or expired authentication token.
  • 404 Not Found: The requested resource URL does not exist.
  • 500 Internal Server Error: Server crashed while processing request.

3. The Modern Fetch API: Syntax & The Two-Step Promise

The global fetch() method initiates a network request and returns a Promise. However, unlike traditional libraries, fetch() requires a two-step resolution: fetch() do steps me kaam karta hai: Pehla promise HTTP response headers aate hi resolve hota hai, aur doosra step body data (JSON ya text) padhne ke liye call hota hai:

JavaScript — Anatomy of a Standard GET Request 
// Standard async/await pattern with fetch
async function loadCourseCatalog() {
  try {
    // Step 1: Network headers returned
    const response = await fetch("https://api.example.com/v1/courses");

    // CRITICAL: Check response.ok! (True if status is 200-299)
    if (!response.ok) {
      throw new Error(`HTTP Error! Status: ${response.status} (${response.statusText})`);
    }

    // Step 2: Stream and parse response body as JSON
    const courses = await response.json();
    console.log("Fetched courses:", courses);
    return courses;
  } catch (error) {
    // Intercepts BOTH real network drops (DNS/offline) AND thrown HTTP errors
    console.error("Failed to load catalog:", error.message);
  }
}
⚠ The Number One Beginner Trap: `fetch()` Rejection Behavior!

A fetch() Promise rejects ONLY when a real network failure occurs (such as no internet connection, DNS failure, or CORS blocked by browser). If the server responds with a 404 Not Found or a 500 Server Crash, fetch() will still happily fulfill the promise! You MUST check if (!response.ok) manually to detect HTTP errors. Bohot important point: fetch() sirf tab reject hota hai jab internet disconnected ho ya DNS fail ho. Agar server 404 ya 500 bhejta hai, toh bhi fetch fulfill hota hai! Isliye hamesha if (!response.ok) check karke error throw karein.

4. Sending Data: HTTP POST with Headers and Payload

To send information to a server (like registering an account, submitting an order, or posting a comment), pass a configuration object as the second argument to fetch(): Server par data submit karne ke liye POST method use karein, headers me Content-Type: application/json set karein aur body me JSON.stringify kiya hua data bhejein:

JavaScript — Submitting POST Request with JSON Body 
async function createNewArticle(articleData) {
  const url = "https://api.example.com/v1/articles";

  const options = {
    method: "POST",
    headers: {
      "Content-Type": "application/json", // Tells server body is JSON
      "Accept": "application/json",
      "Authorization": "Bearer secret_user_jwt_token" // Authentication
    },
    body: JSON.stringify(articleData) // Must be a string, not a raw JS object!
  };

  try {
    const response = await fetch(url, options);

    if (!response.ok) {
      const errDetails = await response.text();
      throw new Error(`Server rejected creation (${response.status}): ${errDetails}`);
    }

    const createdRecord = await response.json();
    console.log("Article created with ID:", createdRecord.id);
    return createdRecord;
  } catch (err) {
    console.error("Article submission failed:", err.message);
  }
}

5. 100% Offline Mock API Simulation

Because this tutorial website runs completely offline without requiring any third-party internet servers, you can build reliable, realistic Mock API Handlers using JavaScript Promises and setTimeout to emulate real network round-trips: Kyunki hamari website bina internet ke offline chalti hai, hum real network roundtrips ko simulate karne ke liye custom Mock API functions banate hain jo exact real fetch jaise behave karte hain:

JavaScript — Clean In-Memory Mock API Engine 
// Mock Database stored in memory
const mockDatabase = [
  { id: 1, title: "Learn Semantic HTML", completed: true },
  { id: 2, title: "Master CSS Flexbox", completed: true },
  { id: 3, title: "Conquer Async JavaScript", completed: false }
];

// Offline Mock Fetch Service
function mockApiFetch(endpoint, options = { method: "GET" }) {
  return new Promise((resolve, reject) => {
    // Emulate 400ms network latency
    setTimeout(() => {
      if (endpoint === "/api/todos" && options.method === "GET") {
        resolve({
          ok: true,
          status: 200,
          json: async () => JSON.parse(JSON.stringify(mockDatabase))
        });
      } else if (endpoint === "/api/todos" && options.method === "POST") {
        const payload = JSON.parse(options.body);
        const newTodo = { id: Date.now(), ...payload };
        mockDatabase.push(newTodo);
        resolve({
          ok: true,
          status: 201,
          json: async () => newTodo
        });
      } else {
        resolve({
          ok: false,
          status: 404,
          statusText: "Not Found",
          json: async () => ({ error: "Route not registered" })
        });
      }
    }, 400);
  });
}

⚠ Common Fetch & JSON Mistakes
  • Passing a raw JavaScript object to body:: Doing fetch(url, { body: userObj }) transmits "[object Object]" to the server, resulting in a 400 Bad Request. You MUST stringify it: body: JSON.stringify(userObj).
  • Forgetting Content-Type: application/json header: Backend web frameworks (like Express or Django) will not parse the body unless the header explicitly declares it as JSON.
  • Trying to read the response body twice: A response body is a readable stream. Calling await response.json() and then await response.text() on the same response throws TypeError: Failed to execute 'text' on 'Response': body stream already read!
💡 Production Best Practices
  • Create an API Client Wrapper: Avoid calling raw fetch() everywhere in your app. Build a centralized apiClient(url, options) utility that automatically attaches base URLs, auth headers, and handles status code checking in one place.
  • Use AbortController for Timeouts: Native fetch() does not have a timeout config option. Use const controller = new AbortController(); fetch(url, { signal: controller.signal }); setTimeout(() => controller.abort(), 5000); to cancel slow requests.
✅ Quick Recap
  • JSON keys and strings must strictly use double quotes; functions and comments are forbidden.
  • JSON.stringify() converts objects into text; JSON.parse() converts text into objects.
  • fetch() returns a promise that resolves when HTTP headers arrive; call response.json() to read the body.
  • fetch() does NOT reject on 404 or 500 status codes — always check response.ok!
  • POST requests require setting method: 'POST', headers: { 'Content-Type': 'application/json' }, and body: JSON.stringify(...).

Exercise 1: Safe JSON Parser

Write a utility function safeJsonParse(jsonString, fallbackValue) that parses the provided string. If valid, return the parsed object; if invalid, catch the error and return fallbackValue without crashing.

View Solution 
function safeJsonParse(jsonString, fallbackValue = {}) {
  try {
    return JSON.parse(jsonString);
  } catch (error) {
    console.warn("JSON Parse Error, using fallback:", error.message);
    return fallbackValue;
  }
}

// Tests:

Hard

Exercise 3: Fetch with Auto-Retry on Network Failure

Write an async function fetchWithRetry(url, maxRetries, delayMs) that attempts a fetch call. If it throws a network error, wait for delayMs and retry up to maxRetries times before throwing the final error.

View Solution 
const wait = ms => new Promise(res => setTimeout(res, ms));

async function fetchWithRetry(url, maxRetries = 3, delayMs = 1000) {
  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      console.log(`Fetch attempt ${attempt} of ${maxRetries}...`);
      const response = await fetch(url);
      if (!response.ok) {
        throw new Error(`HTTP ${response.status}: ${response.statusText}`);
      }
      return await response.json();
    } catch (err) {
      if (attempt === maxRetries) {
        console.error("All retry attempts exhausted.");
        throw err;
      }
      console.warn(`Attempt ${attempt} failed (${err.message}). Retrying in ${delayMs}ms...`);
      await wait(delayMs);
    }
  }
}
