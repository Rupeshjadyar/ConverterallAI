1. Comparing Client-Side Storage Mechanisms

Modern browsers offer several client-side storage options. Choosing the right mechanism depends on data size, persistence requirements, and whether the server needs direct access: Browser me data save karne ke alag-alag tarike hote hain. Har tarike ka capacity aur lifespan alag hota hai:

Storage Type Capacity Limit Lifespan Sent with HTTP Requests? Primary Use Case
Cookies ~4 KB Configurable expiration date Yes (Every HTTP request) Session tokens, auth cookies, tracking
LocalStorage ~5 MB to 10 MB Permanent (until user/code clears) No (Purely client-side) User theme (dark/light), UI state, drafts
SessionStorage ~5 MB Until browser tab closes No (Purely client-side) Multi-step wizards, checkout form state
IndexedDB Hundreds of MB / GBs Permanent No Offline databases, large media, PWA assets

2. The Web Storage API Core Methods

Both localStorage and sessionStorage implement the exact same Storage interface on the global window object. You interact with them using identical method calls: localStorage aur sessionStorage dono me bilkul same methods use hote hain:

JavaScript — Basic Storage CRUD Operations 
// 1. CREATE or UPDATE: setItem(key, value)
localStorage.setItem("themePreference", "dark");
localStorage.setItem("fontSize", "16px");

// 2. READ: getItem(key) -> Returns string or null if not found
const currentTheme = localStorage.getItem("themePreference");
console.log("Current theme:", currentTheme); // "dark"

const missingKey = localStorage.getItem("nonExistentKey");
console.log("Missing key:", missingKey); // null

// 3. DELETE a specific key: removeItem(key)
localStorage.removeItem("fontSize");

// 4. CHECK TOTAL KEYS and loop by index
console.log("Total items stored:", localStorage.length);
for (let i = 0; i < localStorage.length; i++) {
  const keyName = localStorage.key(i);
  console.log(`Key #${i}: ${keyName} = ${localStorage.getItem(keyName)}`);
}

// 5. PURGE EVERYTHING: clear()
// Warning: Wipes all key-value pairs for the current origin!

3. The String-Only Constraint & JSON Serialization

The Web Storage API only stores strings. If you attempt to pass an object, an array, or a boolean, JavaScript will automatically invoke .toString() on it, silently converting your rich data into the useless string "[object Object]"! Web Storage sirf aur sirf text strings store karta hai. Agar aap direct object ya array pass karenge toh JS usko "[object Object]" bana dega. Isliye hamesha JSON.stringify aur JSON.parse use karein:

JavaScript — Storing and Retrieving Objects & Arrays 
// BAD PRACTICE: Storing raw object directly
const user = { name: "Ananya", score: 95 };
localStorage.setItem("user_bad", user);
console.log(localStorage.getItem("user_bad")); // Output: "[object Object]" (Data lost!)

// CORRECT PRACTICE: Always serialize with JSON!
const gameState = {
  player: "Rohan",
  level: 4,
  inventory: ["laser-sword", "health-potion", "shield"],
  highScore: 12400
};

// 1. Serialize object to JSON string before saving
localStorage.setItem("rpg_save_data", JSON.stringify(gameState));

// 2. Retrieve string and parse back into live JavaScript object
const savedDataString = localStorage.getItem("rpg_save_data");

if (savedDataString) {
  const restoredGameState = JSON.parse(savedDataString);
  console.log("Player name:", restoredGameState.player); // "Rohan"
  console.log("Inventory items:", restoredGameState.inventory.length); // 3
} else {
  console.log("No save game found. Initializing new game...");
}

4. Storage Limits & Defensive Quota Handling

Browsers allocate roughly 5MB (sometimes up to 10MB) per origin for localStorage. While 5MB is huge for text settings (approx. 5 million characters), storing large base64 images or massive offline datasets can quickly fill it up. When storage is full, setItem() throws a QuotaExceededError. LocalStorage ki limit lagbhag 5MB hoti hai. Agar limit bhar jaye toh browser QuotaExceededError throw karta hai. Hamesha try-catch me wrap karein:

JavaScript — Defensive Safe Storage Wrapper 
const StorageHelper = {
  set(key, value) {
    try {
      const serialized = JSON.stringify(value);
      localStorage.setItem(key, serialized);
      return true;
    } catch (error) {
      if (error.name === "QuotaExceededError" || error.code === 22) {
        console.error("Storage Quota Exceeded! Purging temporary cache...");
        // Cleanup strategy: Remove non-essential cached entries
        localStorage.removeItem("cached_feed");
      } else {
        console.error("Storage error:", error.message);
      }
      return false;
    }
  },

  get(key, defaultValue = null) {
    try {
      const item = localStorage.getItem(key);
      return item ? JSON.parse(item) : defaultValue;
    } catch (error) {
      console.warn(`Corrupted storage item for key '${key}', returning default.`);
      return defaultValue;
    }
  }
};

5. Cross-Tab Communication with the Storage Event

When two or more tabs of the same website are open in the browser, changes made to localStorage in Tab A automatically fire a 'storage' event inside Tab B and Tab C! This allows you to synchronize user settings (e.g. switching to dark mode or logging out) across all open tabs instantly. Jab ek website ke do tabs open hon aur ek tab me LocalStorage change ho, toh doosre tab me 'storage' event fire hota hai. Isse aap dark mode ya login state ko sabhi tabs me sync kar sakte hain:

JavaScript — Cross-Tab Synchronizer 
// Note: 'storage' event fires ONLY on OTHER tabs/windows of the same origin,
// not in the tab that made the change!
window.addEventListener("storage", function(event) {
  console.log("Storage changed in another tab!");
  console.log("Modified Key:", event.key);
  console.log("Old Value:", event.oldValue);
  console.log("New Value:", event.newValue);
  console.log("Origin URL:", event.url);

  if (event.key === "themePreference") {
    // Apply the newly chosen theme immediately
    document.documentElement.setAttribute("data-theme", event.newValue);
  }

  if (event.key === "auth_user" && event.newValue === null) {
    // User logged out in another tab; log out here too!
    alert("Session ended in another tab. Redirecting to login...");
    window.location.reload();
  }
});

⚠ Common Storage Security & Performance Mistakes
  • Storing Sensitive Credentials: NEVER store unencrypted passwords, credit card numbers, or high-privilege API secret keys in localStorage. Any malicious third-party script injected via XSS (Cross-Site Scripting) can read the entire contents of localStorage with a single line of JavaScript!
  • Synchronous Blocking of UI Thread: Unlike IndexedDB, localStorage is completely synchronous. Reading or writing megabytes of JSON freezes the main JavaScript UI thread, causing noticeable lag and frame drops.
  • Assuming Unlimited Lifetime: Some mobile browsers (like iOS Safari in certain battery-saver or storage-constrained modes) may automatically purge localStorage for sites not visited within 7 days. Use storage as an enhancement, not your only source of truth.
💡 Senior Pro Tips
  • Namespace Your Storage Keys: Prefix your keys with your app name (e.g. app_v1_theme instead of just theme). This prevents naming collisions if multiple scripts or subdomains share origin storage.
  • Version Your Storage Schema: Always store a schema version (e.g. { version: 2, data: ... }). When updating your web app, check the version and migrate or reset old legacy data schemas gracefully.
✅ Quick Recap
  • localStorage persists permanently across sessions; sessionStorage is wiped when the tab closes.
  • Use setItem(key, value), getItem(key), removeItem(key), and clear().
  • Web Storage only accepts strings: always wrap objects in JSON.stringify() and JSON.parse().
  • Storage is bound to the Same-Origin Policy (protocol, domain, port).
  • Listen to window.addEventListener('storage', ...) to sync changes across different open tabs in real time.

function trackVisits() {
  const currentCount = localStorage.getItem("site_visit_count");
  const count = currentCount ? parseInt(currentCount, 10) + 1 : 1;
  localStorage.setItem("site_visit_count", count.toString());

  if (count === 1) {
    console.log("Welcome to your first visit!");

Exercise 2: Storage with Automatic Expiration (TTL)

Write two functions: setWithExpiry(key, value, ttlMs) that stores a value with an expiration timestamp, and getWithExpiry(key) that returns null and removes the key if the expiration time has elapsed.

View Solution 
function setWithExpiry(key, value, ttlMs) {
  const now = new Date();
  const item = {
    value: value,
    expiry: now.getTime() + ttlMs
  };
  localStorage.setItem(key, JSON.stringify(item));
}

function getWithExpiry(key) {
  const itemStr = localStorage.getItem(key);
  if (!itemStr) return null;

  try {
    const item = JSON.parse(itemStr);
    const now = new Date().getTime();
    if (now > item.expiry) {
      // Expired! Delete and return null
      localStorage.removeItem(key);
      return null;
    }
    return item.value;
  } catch (err) {
    return null;
  }
}

// Test with 2 second TTL:
setWithExpiry("temp_discount", "SAVE50", 2000);
console.log(getWithExpiry("temp_discount")); // "SAVE50"
// After 2.5 seconds: getWithExpiry("temp_discount") returns null!
Hard

Exercise 3: Calculate Remaining LocalStorage Capacity

Write a function getStorageUsageInfo() that computes the total bytes currently consumed by all keys and values in localStorage, formatted in Kilobytes (KB) and Megabytes (MB).

View Solution 
function getStorageUsageInfo() {
  let totalChars = 0;
  for (let i = 0; i < localStorage.length; i++) {
    const key = localStorage.key(i);
    const value = localStorage.getItem(key);
    // In UTF-16 (JavaScript strings), each character is roughly 2 bytes
    totalChars += (key.length + value.length);
  }

  const bytes = totalChars * 2;
  const kb = (bytes / 1024).toFixed(2);
  const mb = (bytes / (1024 * 1024)).toFixed(3);

  return {
    itemCount: localStorage.length,
    bytes: bytes,
    kilobytes: kb + " KB",
    megabytes: mb + " MB"
  };
}

console.log(getStorageUsageInfo());
