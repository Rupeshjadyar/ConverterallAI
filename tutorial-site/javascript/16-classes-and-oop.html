1. Defining Classes & The `constructor()`

Introduced in ES6, the class keyword provides clean, familiar syntax for object-oriented design:

Code Example 1: Basic Class Structure

javascript
class User {
  // The constructor runs automatically the microsecond 'new User()' is called!
  constructor(name, email, role = "student") {
    this.name = name;
    this.email = email;
    this.role = role;
    this.createdAt = new Date();
  }

  // Instance Method (Shared on the prototype for zero memory duplication):
  greet() {
    return `Hello, I am ${this.name} (${this.role})`;
  }

  updateEmail(newEmail) {
    this.email = newEmail;
    console.log(`Email updated for ${this.name}: ${this.email}`);
  }
}

// Instantiating objects using 'new':
const userA = new User("Alice", "alice@example.com", "admin");
const userB = new User("Bob", "bob@example.com");

console.log(userA.greet()); // "Hello, I am Alice (admin)"
console.log(userB.greet()); // "Hello, I am Bob (student)"

2. Class Inheritance with `extends` and `super()`

Inheritance allows a child subclass to absorb all methods and properties from a parent class while introducing specialized functionality:

Code Example 2: Subclassing and Method Overriding

javascript
// Subclass extending parent User class
class Instructor extends User {
  constructor(name, email, coursesTeaching = []) {
    // Crucial: super() calls the PARENT constructor!
    // Must be called BEFORE accessing 'this' in constructor!
    super(name, email, "instructor");
    this.coursesTeaching = coursesTeaching;
  }

  // Adding a specialized subclass method:
  assignCourse(courseName) {
    this.coursesTeaching.push(courseName);
    console.log(`${this.name} is now teaching: ${courseName}`);
  }

  // METHOD OVERRIDING (Polymorphism):
  // Replaces parent greet() method with specialized behavior:
  greet() {
    return `Professor ${this.name} reporting for duty! Teaching ${this.coursesTeaching.length} courses.`;
  }
}

const prof = new Instructor("Dr. Henderson", "henderson@univ.edu", ["Data Structures"]);
console.log(prof.greet()); // Overridden greeting!
prof.assignCourse("Advanced Algorithms");

3. Data Validation with Getters and Setters

Getters and setters allow you to intercept property reads and writes, enabling data validation and computed properties that look like standard variables:

Code Example 3: Getters & Setters

javascript
class Temperature {
  constructor(celsius) {
    this._celsius = celsius; // Underscore indicates internal property
  }

  // GETTER: Computed read property
  get fahrenheit() {
    return (this._celsius * 9/5) + 32;
  }

  // SETTER: Validated write property
  set celsius(val) {
    if (val < -273.15) {
      throw new RangeError("Temperature below absolute zero is physically impossible!");
    }
    this._celsius = val;
  }
}

const temp = new Temperature(25);
// Notice we access fahrenheit as a property WITHOUT parentheses!
console.log(`${temp.fahrenheit}°F`); // 77°F

temp.celsius = 30; // Triggers setter!
console.log(`${temp.fahrenheit}°F`); // 86°F

4. Static Methods & Properties

The static keyword defines methods or constants that belong directly to the Class itself rather than individual instances (e.g. factory creators or helpers):

Code Example 4: Static Utility Methods

javascript
class MathHelper {
  // Static Constant:
  static PI = 3.14159265359;

  // Static Factory Method:
  static calculateCircleArea(radius) {
    return this.PI * (radius ** 2);
  }
}

// Call directly on the Class constructor WITHOUT creating 'new':
console.log(MathHelper.calculateCircleArea(10)); // ~314.159

// An instance CANNOT access static methods directly:
// const helper = new MathHelper();
// helper.calculateCircleArea(10); // TypeError: helper.calculateCircleArea is not a function!

5. Hard Native Privacy: Private Class Fields (`#`)

Historically, JavaScript developers used convention prefixes (like _privateVar) that were still accessible from outside. Modern JavaScript includes True Native Private Fields using the hashtag (#) prefix:

Code Example 5: Private Fields

javascript
class BankVault {
  // 1. Declare private fields with '#'
  #pinCode;
  #balance;

  constructor(initialPin, initialDeposit) {
    this.#pinCode = initialPin;
    this.#balance = initialDeposit;
  }

  // Public method with authorization gatekeeper:
  withdraw(pin, amount) {
    if (pin !== this.#pinCode) {
      return "ACCESS DENIED: Incorrect PIN code.";
    }
    if (amount > this.#balance) {
      return "TRANSACTION FAILED: Overdraft limit exceeded.";
    }
    this.#balance -= amount;
    return `Withdrawal successful. Remaining: $${this.#balance}`;
  }
}

const vault = new BankVault(1234, 1000);

// ATTEMPTING TO READ PRIVATE FIELDS CRASHES WITH SYNTAX ERROR:
// console.log(vault.#pinCode); // SyntaxError: Private field '#pinCode' must be declared in an enclosing class!
console.log(vault.withdraw(1234, 200)); // "Withdrawal successful..."

⚠ Common Beginner Mistakes
  • Forgetting super() in subclass constructors: If a class uses extends, its constructor MUST invoke super(...) before accessing this. Failing to do so throws a fatal ReferenceError!
  • Invoking getters like methods: Writing temp.fahrenheit() throws TypeError: temp.fahrenheit is not a function! Getters are accessed as properties: temp.fahrenheit.
  • Recursion bug in setters: Writing set age(val) { this.age = val; } causes an infinite loop and stack overflow because assignment inside setter invokes the setter again! Store in a different property (like this.#age or this._age).
  • Assuming classes are hoisted: Unlike function declarations, class declarations are NOT hoisted! You cannot instantiate new Car() before its class definition line.
💡 Pro Tips from Senior Engineers
  • Prefer Composition over Inheritance: While inheritance (extends) is useful, deep multi-level inheritance hierarchies (5+ levels) become fragile. Prefer composing small modular objects where possible.
  • Static factory patterns: Use static methods like User.fromJSON(rawString) to cleanly parse and construct class instances from external API payloads.
  • instanceof Operator: Use myCar instanceof Vehicle to check if an object was built from a specific class constructor or its parent hierarchy.
⚡ Quick Recap
  • Classes serve as blueprints for producing multiple instances using new.
  • The constructor() executes automatically during instantiation.
  • Subclasses use extends and must call super() before accessing this.
  • Getters (get) and setters (set) provide controlled computed properties.
  • static methods belong directly to the constructor, not instances.
  • Private fields use the hashtag syntax #fieldName for native encapsulation.

7. Practice Coding Exercises

Exercise 1 (Easy): Basic Class Construction Easy

Write a class Book with a constructor that takes title and author, and a method getSummary() returning "[title] by [author]".

Hint: class Book { constructor(title, author) { ... } getSummary() { ... } }
Solution:
class Book {
  constructor(title, author) {
    this.title = title;
    this.author = author;
  }
  getSummary() {
    return `${this.title} by ${this.author}`;
  }
}
Exercise 2 (Medium): Subclassing with Super Medium

Extend the Book class from Exercise 1 with an EBook class that accepts an extra parameter fileSizeMB and sets it on the instance.

Hint: class EBook extends Book { constructor(title, author, fileSizeMB) { super(title, author); ... } }
Solution:
class EBook extends Book {
  constructor(title, author, fileSizeMB) {
    super(title, author);
    this.fileSizeMB = fileSizeMB;
  }
}
Exercise 3 (Hard): Private Balance Wallet Hard

Create a Wallet class with a private field #cash initialized in the constructor. Provide a getter balance and a method addCash(amount) that validates amount > 0 before adding.

Hint: #cash = 0; get balance() { return this.#cash; }
Solution:
class Wallet {
  #cash = 0;

  constructor(initialCash = 0) {
    this.#cash = initialCash;
  }

  get balance() {
    return this.#cash;
  }

  addCash(amount) {
    if (amount > 0) {
      this.#cash += amount;
    }
  }
}
