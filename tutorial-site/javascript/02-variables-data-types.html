1. Declaring Variables: let vs const vs var

Before ES6 (2015), JavaScript only had the var keyword. Today, modern senior developers follow a strict rule:

The Senior Standard: Default to const for 90% of your code. Use let only when you know a value must be reassigned (like loop counters). NEVER use legacy var.

Code Example 1: `const` vs `let` in Action

javascript
// 1. const: Cannot be reassigned
const birthYear = 2000;
// birthYear = 2001; // ERROR: TypeError: Assignment to constant variable.

// 2. let: Can be reassigned smoothly
let score = 0;
score = 10; // Perfectly valid!
score = score + 5; // Now 15

// 3. var (LEGACY): Has dangerous function scope and allows duplicate declarations
var city = "New York";
var city = "London"; // No warning! Silently overwrites previous data.

2. The 7 Primitive Data Types

In JavaScript, a primitive is data that is not an object and has no methods of its own. Primitives are immutable:

Code Example 2: The 7 Primitives Declared

javascript
// 1. String: Text wrapped in single, double, or backtick quotes
const name = "Alice";
const greeting = `Hello, ${name}!`; // Template literal

// 2. Number: Both integers and floating-point decimals
const age = 28;
const price = 19.99;
const invalidMath = 0 / 0; // NaN (Not a Number - but type is 'number'!)

// 3. Boolean: Logical truth values
const isLoggedIn = true;
const hasSubscription = false;

// 4. Undefined: A variable that was declared but never assigned a value
let unassignedBox;
console.log(unassignedBox); // undefined

// 5. Null: Intentional absence of any object value (empty on purpose)
const selectedProduct = null;

// 6. BigInt: Whole numbers larger than (2^53 - 1)
const nationalDebt = 9007199254740995n; // Notice trailing 'n'

// 7. Symbol: Guaranteed unique, immutable identifier
const idA = Symbol("apiKey");
const idB = Symbol("apiKey");
console.log(idA === idB); // false! Always unique.

3. Type Inspection with typeof

The typeof operator evaluates the data type of an expression:

Code Example 3: Inspecting Types and the Historic Null Bug

javascript
console.log(typeof "Hello");     // "string"
console.log(typeof 42);          // "number"
console.log(typeof true);        // "boolean"
console.log(typeof undefined);   // "undefined"
console.log(typeof 100n);        // "bigint"
console.log(typeof Symbol());    // "symbol"
console.log(typeof { a: 1 });    // "object"

// THE FAMOUS 1995 HISTORIC BUG:
console.log(typeof null);        // "object"! 
// In the first version of JS, values were stored with a 32-bit type tag.
// The type tag for objects was 0. Null was a null pointer (0x00).
// Therefore, typeof null returned "object". It is never fixed to avoid breaking legacy web code!

4. Primitives (Values) vs Objects (References)

Understanding how memory allocates data is the dividing line between junior and senior engineers:

Code Example 4: Value Copy vs Reference Sharing

javascript
// PRIMITIVES (Stored by VALUE on the Call Stack):
let a = 10;
let b = a; // Makes an independent copy of the value 10
b = 20;
console.log(a); // 10 (Remains completely unaffected!)

// REFERENCE TYPES (Stored by REFERENCE on the Memory Heap):
const user1 = { name: "Bob" };
const user2 = user1; // Copies the MEMORY ADDRESS pointer, NOT the object!
user2.name = "Charlie";

console.log(user1.name); // "Charlie"! Both variables point to the exact same memory box!

5. The `const` Mutation Secret

Beginners are often terrified of using const with arrays or objects because they think the data can never be modified.

Crucial Insight: const protects the variable binding (the pointer memory address). It does NOT freeze the internal contents of an object or array!

Code Example 5: Mutating const Objects & Arrays

javascript
const cart = ["Apple", "Banana"];

// 1. Mutating contents is 100% legal:
cart.push("Orange");
cart[0] = "Avocado";
console.log(cart); // ["Avocado", "Banana", "Orange"]

// 2. Reassigning the pointer is ILLEGAL:
// cart = ["New", "Array"]; // ERROR: TypeError: Assignment to constant variable.

⚠ Common Beginner Mistakes
  • Reassigning a const variable: const x = 5; x = 6; throws a fatal TypeError that halts your program. Use let when reassignment is expected.
  • Using variables before declaration (TDZ): Accessing a let or const variable before its line of declaration throws a ReferenceError because it sits in the Temporal Dead Zone.
  • Confusing null and undefined: undefined means the variable was declared but no one set a value. null is an intentional assignment representing "no value".
  • Assuming typeof NaN is not a number: Ironically, typeof NaN === "number" in JavaScript! NaN stands for a numerical computation that failed to yield a valid number (like "cat" * 5).
💡 Pro Tips from Senior Engineers
  • CamelCase naming convention: Always name JavaScript variables in lowerCamelCase (e.g. userProfileImage, totalCartPrice). Reserve PascalCase (UserCard) for classes.
  • Freeze objects with Object.freeze(): If you truly want an object's internal properties to be immutable, wrap it: const config = Object.freeze({ api: "https://api.com" });.
  • Verify arrays with Array.isArray(): Because typeof [] returns "object", use Array.isArray(myVar) to accurately test if a variable is an array!
⚡ Quick Recap
  • Default to const; use let only when reassigning; avoid var.
  • 7 Primitives: string, number, boolean, null, undefined, symbol, bigint.
  • Primitives are copied by value; Objects/Arrays are copied by memory reference pointer.
  • typeof null returns "object" due to a historic 1995 legacy bug.
  • const prevents rebinding, but object properties and array elements can still be mutated.
  • Use Array.isArray(x) to accurately identify arrays.

7. Practice Coding Exercises

Exercise 1 (Easy): Choose the Correct Keyword Easy

Declare a variable named userScore with initial value 0 that will increment as the user plays a game. Which keyword (let or const) should you use?

Hint: The value changes over time.
Solution:
let userScore = 0; (Use let because the score will be reassigned).
Exercise 2 (Medium): Check for Array Type Medium

Why is typeof items === "array" invalid, and what is the correct standard JavaScript method to test if items is an array?

Hint: Array.isArray().
Solution:
typeof [] returns "object", not "array". The correct check is: Array.isArray(items).
Exercise 3 (Hard): Predict the Reference Output Hard

What will be logged to the console?
const a = { val: 5 }; const b = a; b.val = 10; console.log(a.val);

Hint: Objects are copied by memory reference, not by value.
Solution:
10. Because objects are stored by reference, variable b points to the exact same object in memory as a.
