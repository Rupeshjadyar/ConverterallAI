1. Arithmetic & Assignment Operators

JavaScript provides standard mathematical arithmetic operations:

Code Example 1: Math Operations & Modulo

javascript
const sum = 10 + 4;         // 14
const diff = 10 - 4;        // 6
const product = 10 * 4;     // 40
const quotient = 10 / 4;    // 2.5
const exponent = 2 ** 3;    // 8 (2 to the power of 3)

// THE MODULO OPERATOR (%): Returns remainder of division
const remainder = 10 % 3;   // 1 (10 / 3 = 3 with remainder 1)

// Pro Tip: Modulo tests if a number is Even or Odd:
const isEven = (num) => num % 2 === 0;

// Compound Assignments:
let count = 10;
count += 5; // count = count + 5 (15)
count *= 2; // count = count * 2 (30)

2. Strict Equality (===) vs Loose Equality (==)

This is one of the most tested topics in frontend technical interviews:

Operator Name Behavior Example
=== Strict Equality Checks BOTH value AND type. No coercion. 5 === "5" → false
== Loose Equality Coerces types behind your back before comparing. 5 == "5" → true (Dangerous!)
!== Strict Inequality Checks if value or type is different. 5 !== "5" → true

Code Example 2: The Pitfalls of Loose Equality

javascript
// The Bizarre Quirks of Loose Equality (==):
console.log(0 == false);        // true! (0 coerced to boolean)
console.log("" == 0);           // true! (empty string coerced to 0)
console.log(null == undefined); // true!
console.log([] == 0);           // true!

// With Strict Equality (===), Everything makes clean mathematical sense:
console.log(0 === false);        // false! (number vs boolean)
console.log("" === 0);           // false! (string vs number)
console.log(null === undefined); // false!

3. Logical Operators & Short-Circuiting

Logical operators (&&, ||, ??) evaluate from left to right and can return non-boolean values:

Code Example 3: Short-Circuit Fallbacks

javascript
// 1. Logical OR (||): Returns the FIRST TRUTHY value, or the last falsy value
const displayName = userInput || "Anonymous Guest";

// 2. Logical AND (&&): Short-circuits on the FIRST FALSY value
// Great for conditional execution:
isLoggedIn && showDashboard();

// 3. Nullish Coalescing (??): Checks ONLY for null or undefined (ignores 0 and "")
const userScore = 0;
const finalScore1 = userScore || 10;  // 10 (BUG! 0 is falsy, so it replaced 0!)
const finalScore2 = userScore ?? 10;  // 0  (CORRECT! 0 is not null or undefined)

4. The 8 Falsy Values in JavaScript

When evaluated in a boolean context (like an if condition), exactly eight values convert to false. Every other value in JavaScript is truthy (including empty arrays [] and empty objects {}!):

1. false
2. 0 (zero)
3. -0 (negative zero)
4. 0n (BigInt zero)
5. "" (empty string)
6. null
7. undefined
8. NaN (Not a Number)

5. Explicit Conversion vs Implicit Coercion

Senior developers write explicit conversions so team members never have to guess what type is produced:

Code Example 4: Explicit Conversion Methods

javascript
// 1. Converting to Number:
const input = "42";
const num1 = Number(input);      // 42
const num2 = parseInt("42px");   // 42 (stops parsing at non-digit!)
const num3 = parseFloat("3.14"); // 3.14
const num4 = +"42";              // Unary plus shortcut

// 2. Converting to String:
const count = 120;
const str1 = String(count);      // "120"
const str2 = count.toString();   // "120"

// 3. Converting to Boolean:
const bool1 = Boolean("hello");  // true
const bool2 = Boolean("");       // false
const bool3 = !!"hello";         // Double bang shortcut: true

6. The Quirks of Implicit Coercion Explained

Why does "5" + 2 equal "52", but "5" - 2 equals 3?

Code Example 5: String Concatenation vs Arithmetic Coercion

javascript
// The '+' operator is OVERLOADED:
// If either operand is a string, '+' acts as STRING CONCATENATION:
console.log("5" + 2);   // "52" (number 2 coerced to string)
console.log(2 + 2 + "5"); // "45" (2+2 evaluates first to 4, then 4 + "5" = "45")

// The '-' operator has NO string meaning:
// JavaScript forces both sides to convert to NUMBERS:
console.log("5" - 2);   // 3
console.log("10" * "2");// 20
console.log("10" / "2");// 5
console.log("five" - 2);// NaN ("five" cannot convert to number)

⚠ Common Beginner Mistakes
  • Using == instead of ===: Loose equality leads to subtle, hard-to-diagnose authentication and calculation bugs. Use === exclusively.
  • Adding numbers from HTML inputs without conversion: input.value is ALWAYS a string. If the user types 10 and 20, writing val1 + val2 yields "1020" instead of 30! Wrap with Number(input.value).
  • Using || when 0 is a valid value: userCartCount || 5 will replace 0 with 5. Use the modern nullish coalescing operator: userCartCount ?? 5.
  • Thinking [] is falsy: In JavaScript, all objects and arrays (even empty ones [] and {}) are truthy!
💡 Pro Tips from Senior Engineers
  • Fast numerical parsing with unary plus: const num = +inputStr; is the cleanest and fastest way to coerce a string to a number.
  • Double negation boolean cast (!!): Writing !!user cleanly casts any object, string, or number to a pure boolean true or false.
  • Use Number.isNaN() instead of isNaN(): The global isNaN("hello") returns true because it coerces the string first. Number.isNaN() strictly tests without coercion.
⚡ Quick Recap
  • Always use strict equality === and strict inequality !==.
  • The 8 falsy values: false, 0, -0, 0n, "", null, undefined, NaN.
  • || falls back on falsy values; ?? falls back ONLY on null or undefined.
  • + concatenates strings if either side is a string; -, *, / coerce to numbers.
  • HTML input values are always strings; convert explicitly with Number().

8. Practice Coding Exercises

Exercise 1 (Easy): Even Number Test Easy

Write an expression using the modulo operator (%) that evaluates to true if a variable num is an even number.

Hint: Remainder when divided by 2 is 0.
Solution:
num % 2 === 0
Exercise 2 (Medium): Safe Zero Fallback Medium

A user has a variable let balance = 0;. Write a fallback expression that assigns balance to displayBalance, falling back to 100 ONLY if balance is null or undefined.

Hint: Use the nullish coalescing operator ??.
Solution:
const displayBalance = balance ?? 100;
Exercise 3 (Hard): Predict Complex Coercion Hard

What is the exact result and data type of evaluating: 10 + "5" - 2?

Hint: Left-to-right evaluation. 10 + "5" evaluates first, then subtracts 2.
Solution:
Step 1: 10 + "5" → "105" (string concatenation)
Step 2: "105" - 2 → 103 (number subtraction coerces to number!)
Result: 103 (number).
